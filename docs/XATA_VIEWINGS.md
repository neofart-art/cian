# Просмотры, отказы и сравнение квартир

Используются прежние property_visits, properties, API просмотров и сессии XATA.
Просмотры принадлежат реальной квартире (property), сохраняются при обычном
импорте, перепубликации и ручном объединении дублей. Collector, matcher,
ипотечная формула, Compose, порт 3010 и persistent volumes не меняются.

## Дата без времени и подтверждение «ОК»

В колонке «Дата просмотра» видна только дата ДД.ММ.ГГГГ, независимо от языка
и часового пояса браузера. Администратор и риелтор видят компактное поле,
календарь и кнопки «Очистить» и «ОК». Покупатель (reviewer) видит значение.

Ввод/выбор даты, change и потеря фокуса ничего не сохраняют. «Очистить»
также меняет только черновик. Единственное действие сохранения — «ОК».
Незаполненные и некорректные черновики не затираются фоновым обновлением.
Повторное подтверждение неизменённой даты не пишет данные и не повышает версии.
Кнопки блокируются во время запроса; повторное нажатие не создаёт дубль.

Сохраняется прежняя запись показанного просмотра по ID: у planned меняется
scheduled_at, у completed — completed_at. У существующего timestamp при смене
дня сохраняются московское время и микросекунды. Неизменённый день сохраняет
timestamp полностью. Результат, заметки, причины и обе оценки не меняются.
Новая календарная встреча хранится как начало выбранного дня в Москве,
нормализованное в UTC: например 26.10.2026 → 2026-10-25T21:00:00+00:00.
Это якорь хранения календарной даты, а не выбранное пользователем время.

Подтверждённая очистка плановой даты отменяет встречу, сохраняя её дату/историю.
Удаление фактической даты состоявшегося просмотра по-прежнему запрещено.
При конфликте 409 чужое изменение не затирается, черновик остаётся в поле;
обновите страницу, чтобы начать от актуальной записи/версии.

Права inline-операции проверяются сервером: только admin/realtor. По уточнению
владельца это ограничение относится только к колонке. Существующая форма
результата, её datetime-local, права семьи/администратора, результат, заметки
и причины не менялись. В колонке результата остаётся одна кнопка
«Добавить результат», открывающая ту же форму и существующую запись.

Новых миграций/столбцов/таблиц нет. Используются прежние записи и версии.
Колонка и поле сужены под дату и две кнопки; на телефоне обе кнопки не меньше
44 px по высоте, «ОК» не меньше 44 px по ширине. Прокрутка остаётся внутри таблицы.

## Дата и результат

В таблице две колонки: «Дата просмотра» и «Результат просмотра».

Дата — ближайшая назначенная встреча (включая просроченную), а при её отсутствии —
последний состоявшийся просмотр по фактической дате. Отменённые встречи не
подменяют эту дату. Без даты показывается «—». Заголовок даты переключает
возрастание, убывание и стандартный порядок; неизвестные даты всегда в конце. Сравнивается московский календарный день, показанный в колонке; скрытое время не определяет порядок одинаковых дат.

Все даты интерфейса московские (Europe/Moscow), хранение — UTC.
Плановая и фактическая дата различаются: при записи результата плановая дата
сохраняется, фактическая по умолчанию текущая и редактируется пользователем.

Семья (reviewer) и администратор назначают/переносят/отменяют встречи и
записывают общий результат. Риелтор читает историю. В мобильном редакторе
две крупные кнопки «Понравилось» и «Не понравилось». Достаточно выбрать
результат и сохранить; комментарии и причины не обязательны. Можно записать
результат без предварительного назначения. Прежний результат «Думаем»
сохраняется и редактируется без обязательного выбора новой оценки;
третьей кнопки для него нет.

Результат «Понравилось» → семейный liked, «Не понравилось» → rejected.
Прежний thinking сохраняет прежнюю семантику viewed. Запись результата и
семейной оценки выполняется в одной SQLite-транзакции. Планирование,
перенос, отмена, изменение только заметок/причин не переустанавливают
семейный статус. Результат более старого по фактической дате просмотра
не перекрывает более поздний результат. Независимая оценка риелтора не меняется.

Для повторной поездки создаётся новая запись. Состоявшийся просмотр нельзя
превратить в запланированный или отменённый. История содержит обе заметки,
причины отказа, даты, автора и время последнего изменения.

## Ближайшие просмотры

Отдельное представление показывает только planned, отсортированные по дате и
времени, начиная с ближайших. Счётчик показывает число встреч, а не квартир.
Одна квартира с двумя назначенными встречами занимает две записи.

У встречи видны дата/время, адрес, ЦИАН, заметка «Что проверить / спросить»,
действия «Записать результат», «Перенести», «Отменить».
Просрочка определяется только по московскому календарному дню: дата раньше сегодняшней, не час внутри сегодняшнего дня. Встреча на сегодня не просрочена, даже если технический timestamp уже прошёл.
Просроченная встреча остаётся planned и получает отметку
«Укажите результат просмотра», также видимую в колонке даты.
Время само не меняет ни результат, ни семейный статус.

Назначенные встречи по отказанным квартирам остаются в этом представлении
с отметкой «Не подходит — встреча ещё не отменена» и возможностью отмены.
В основной список это квартиру не возвращает. Внешних уведомлений нет.

## Заметки и причины

preparation («Что проверить / спросить») и comment («Впечатление после
просмотра») независимы, каждое поле до 2000 символов. Черновик открытого
редактора не меняется при фоновом обновлении таблицы.

Для rejected необязательные причины:
noise — Шум; layout — Планировка; condition — Состояние квартиры;
building — Дом / подъезд; location — Расположение;
documents — Документы; other — Другое.
Можно выбрать несколько, сохранить без причин или оставить свободный комментарий.
Причины принадлежат конкретному просмотру, видны в истории и отказах.
При исправлении результата на положительный причины очищаются.
API-клиент, не передающий новые поля, при обычном редактировании прежнего
отрицательного результата не стирает его причины или фактическую дату.

## Не подходят

Под основным списком расположен details «Не подходят — N», при загрузке
страницы закрытый. Строка относится к отказам, если текущий семейный статус
rejected либо текущая оценка риелтора rejected. Квартира существует в одном
из двух списков, фотографии и вся история остаются. Основные фильтры и
сортировка не открывают раздел. Счётчик «Все» учитывает основной список,
число отказов показывается отдельно.

Квартира возвращается, когда обе действующие оценки перестают быть отказом.
Исторический отрицательный просмотр сам по себе возврат не блокирует.
При отказе риелтора семья видит пояснение, но не получает права менять его
оценку. Изменение списка перемещает существующий DOM-узел, сохраняя черновики
комментариев риелтора и раскрытые детали.

## Сравнение

Отметьте 2–4 квартиры в основном списке и нажмите «Сравнить».
Ограничение относится к числу объектов, а не публикаций ЦИАН.
Выбор локальный для открытой страницы, при перезагрузке очищается;
данные просмотров и решений хранятся в SQLite.

В сравнении: одно заглавное фото, ЦИАН, адрес/ЖК, цена, цена за м²
(только при известной цене и положительной площади), площадь/этаж,
метро/время, ипотека по прежней формуле, семейная и риелторская оценки,
комментарий риелтора, дата/результат/комментарий последнего состоявшегося
просмотра. Пропуски — «—». На телефоне таблица прокручивается внутри блока.

Сравнение не вызывает write API и не меняет оценки. Автоматического рейтинга
нет. При отказе выбранная квартира удаляется из сравнения с сообщением,
в том числе внутри открытого диалога. Перепубликация сохраняет выбор по property;
после исчезновения/объединения выбранного property устаревший выбор удаляется.

## API поля даты

PATCH /api/listings/{id}/visits/date, обычная сессия + CSRF.
Только admin/realtor. Тело:
property_id, visits_version, visit_id (null для первой встречи),
date, request_id (UUID для создания).

date принимает новый ISO calendar day YYYY-MM-DD, null для очистки и прежний
aware datetime. Наивные datetime и некорректные дни запрещены. Прежние API-клиенты
с timestamp продолжают работать; API истории и SQLite сохраняют timestamp в UTC.
Для календарной даты используется Europe/Moscow, включая исторические смещения;
часовой пояс браузера/хоста не участвует в выборе дня. Преобразование проверяется
и в собранном Docker-образе app.

Лишние поля (результат, заметки, оценки) запрещены. Проверяются property,
актуальная общая версия и ID показанного просмотра. Повтор одного назначения
возвращает уже сохранённую встречу; одинаковый день не повышает версии.
Изменение даты не вызывает синхронизацию семейной оценки.
Внутренние поля request_id/request_hash прежней таблицы используются повторно.

## API и миграция

Прежние POST /api/listings/{id}/visits и
PATCH /api/listings/{id}/visits/{visit_id}, обычная сессия и CSRF.
Права и version/property_id проверки сохранены; устаревшая правка получает 409
и не затирает чужую запись или пользовательский черновик в редакторе.

К прежнему VisitInput добавлены completed_at (aware datetime либо null),
rejection_reasons (необязательный список кодов) и request_id
(необязательный UUID для POST). Для planned обязателен scheduled_at;
для completed — outcome. Сервер нормализует обе даты в UTC.

Миграция идемпотентно добавляет три поля к существующей property_visits:
- rejection_reasons TEXT NOT NULL DEFAULT '[]';
- request_id TEXT NULL;
- request_hash TEXT NULL.

Плюс уникальный partial index для непустого request_id. Прежняя таблица
не пересоздаётся, неизвестные столбцы/индексы/триггеры и старые данные
сохраняются. completed_at уже существует в предыдущей версии.

Редактор создаёт UUID один раз на новую запись. Повтор того же запроса
возвращает сохранённое состояние без второй встречи, повышения версии и
повторного применения семейной оценки. Другой payload с тем же UUID получает
409. PATCH использует существующую optimistic version. request_id/hash
не выдаются в истории. Кнопки блокируются на время сохранения.

Excel сохраняет прежние листы и колонки. В конце листа «Просмотры» добавлены
читаемые «Причины отказа»; обе заметки и фактическая дата остаются.
Пользовательские строки отображаются textContent; формульные префиксы в XLSX
экранируются, как раньше.

## Проверки

Полный XATA checks: pytest, Node regressions, JavaScript syntax, обе конфигурации
Compose, offline Chromium DOM/UI, сборка обоих образов, healthcheck browser и
noVNC с сохранением профиля. В CI добавлена syntax-проверка compare.js.
Реальный ЦИАН и OMV этими тестами не проверяются.

tests/test_viewing_date.py и Chromium-сценарии проверяют роли, прежние права
формы, CSRF, подтверждение/очистку по «ОК», отсутствие запросов на change/blur,
черновики при polling/409, UTC/Moscow включая границу года и исторический DST,
сохранение прежнего времени/ID/результата, сортировку и повторные запросы.
UI запускается с английской локалью и часовыми поясами Лос-Анджелеса/Токио,
проверяет ДД.ММ.ГГГГ, сегодняшний/вчерашний день и десктопную/мобильную ширину.

Регрессии покрывают старую схему с thinking/неизвестным столбцом/индексом/
триггером, повтор миграции, фактическую дату, обе заметки/причины, XLSX,
хронологию результатов, одновременные POST, повторный запрос, сортировку дат,
счётчик встреч, просроченные/отказанные встречи, права/409, мобильный редактор,
скрытие и возврат отказов, сравнение и его обновление при новом отказе.

## Безопасное обновление OMV

Deployment выполняет владелец. Завершите поиск и используйте прежний каталог
проекта, .env, compose project xata. Не меняйте NPM, порт 3010,
xata_xata_data и xata_browser_profile. Временный noVNC должен быть выключен.

Для изменений относительно 255f8dec нужен только app; browser/collector
не менялись. Если пропущено предыдущее обновление с фотографиями, следуйте
также docs/XATA_COVER_PHOTOS.md и пересоберите browser для нового DOM parser.

1. Проверьте git status --short, ветку и volumes:

~~~sh
git status --short
git branch --show-current
docker compose -p xata ps
docker inspect "$(docker compose -p xata ps -q app)" --format '{{range .Mounts}}{{println .Name .Destination}}{{end}}'
docker inspect "$(docker compose -p xata ps -q browser)" --format '{{range .Mounts}}{{println .Name .Destination}}{{end}}'
~~~

Ожидаются xata_xata_data:/data и xata_browser_profile:/profile.
Несвязанные изменения сохраните, не используйте reset --hard.

2. До git pull создайте согласованную резервную копию всего /data, .env и SHA:

~~~sh
(
set -eu
umask 077
xata_backup="backups/xata-before-viewings-compare-$(date -u +%Y%m%dT%H%M%SZ)"
mkdir -p "$xata_backup"
git rev-parse HEAD > "$xata_backup/git.sha"
cp .env "$xata_backup/.env"
docker compose -p xata stop app
trap 'docker compose -p xata start app' EXIT
docker compose -p xata cp app:/data "$xata_backup/data"
test -s "$xata_backup/data/xata.sqlite3"
echo "Backup: $xata_backup"
)
~~~

При ошибке копирования не продолжайте обновление. Перенесите копию вне сервера.
Не публикуйте .env и SQLite. Browser и его профиль на этом шаге не трогайте.

3. После успешного CI получите изменения и обновите только app:

~~~sh
(
set -eu
test -z "$(git status --porcelain --untracked-files=no)"
git switch xata/initial-app
git pull --ff-only origin xata/initial-app
docker compose -p xata config --quiet
docker compose -p xata -f docker-compose.yml -f docker-compose.browser-login.yml config --quiet
docker compose -p xata build app
docker compose -p xata up -d --no-deps app
curl --fail --show-error --retry 15 --retry-connrefused --retry-delay 2 http://172.31.1.1:3010/healthz
docker compose -p xata ps
)
~~~

При запуске выполняется миграция. Проверьте старые статусы, фото и историю;
назначение/перенос/отмену, оба результата с телефона, заметки и причины;
раздел отказов и возврат; ближайшие встречи и сравнение; CSV и XLSX.
Для диагностики: docker compose -p xata logs --tail=80 app.

Для отката сначала сохраните свежую копию /data, остановите app, вернитесь
к SHA из backup, пересоберите и запустите app с прежним volume. Для предыдущей
версии 255f8dec добавленные поля допустимы, новые причины она не показывает.
Не восстанавливайте старую БД поверх новых решений без отдельного решения
владельца: это потеряет изменения после backup. Права /data остаются UID/GID
10001. Никогда не выполняйте down -v, volume prune и очистку профиля.
