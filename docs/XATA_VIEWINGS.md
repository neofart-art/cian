# Просмотры квартир

В таблице появилась колонка «Просмотр». Семья (reviewer) и администратор могут
назначать встречи, переносить/отменять их и записывать один общий семейный итог.
Риелтор читает историю. Его оценка остаётся независимой.

- Все даты в интерфейсе — московские (Europe/Moscow), хранение — UTC.
- «Запланированные» открывает список встреч по дате с адресом, ссылкой на ЦИАН
  и кнопкой «Итог просмотра»; он рассчитан в том числе на телефон.
- До поездки и после неё — две отдельные необязательные заметки, до 2000 символов.
- При наступлении времени встречи появляется «Укажите результат просмотра».
  Само время не переводит встречу в состоявшиеся и не меняет семейную оценку.
- Можно выбрать «Состоялся» и записать итог без предварительного назначения даты.
- Результаты: «Понравилось» → liked, «Не понравилось» → rejected,
  «Думаем» → viewed. Обновление встречи и статуса происходит в одной транзакции.
- Запись комментария без смены результата, назначение/перенос/отмена повторной
  встречи не переустанавливают семейный статус. Исправление старого результата
  не перекрывает результат более позднего состоявшегося просмотра.
- Состоявшийся просмотр нельзя превратить в отменённый или запланированный:
  для повторной поездки создаётся новая запись, история остаётся.
- Сохраняются автор и время последнего изменения. Версия записи защищает от
  перезаписи параллельных правок: при 409 закройте редактор и откройте заново.
- В XLSX добавлен лист «Просмотры» с историей, датами UTC и заметками.

## Данные и совместимость

Существующая транзакционная миграция идемпотентно добавляет таблицу
`property_visits` и `properties.visits_version`. Пользовательские оценки,
first_seen, фото, публикации, цены и решения по дублям не сбрасываются.
Просмотры принадлежат property: при перепубликации они остаются на квартире,
при ручном объединении переносятся к итоговому property вместе с историей.
Версии защищают интерфейс от устаревших ответов автообновления.

API (обычная сессия и CSRF): POST `/api/listings/{id}/visits`,
PATCH `/api/listings/{id}/visits/{visit_id}`. Тело: property_id, version
(0 для новой записи), status (planned/completed/cancelled), scheduled_at
(ISO datetime с часовым поясом или null), outcome (liked/rejected/thinking
для completed, иначе null), preparation, comment. При обновлении передаётся
текущая версия встречи. История доступна в `/api/state` в поле visits.

## Обновление OMV

Затронут только app, browser не пересобирайте. Миграция выполняется при запуске.
Перед обновлением завершите сбор, сохраните текущий SHA, .env и весь /data.
Из корня прежнего проекта, с прежними volumes:

```sh
(
set -eu
umask 077
xata_backup="backups/xata-before-viewings-$(date -u +%Y%m%dT%H%M%SZ)"
mkdir -p "$xata_backup"
git rev-parse HEAD > "$xata_backup/git.sha"
cp .env "$xata_backup/.env"
docker compose -p xata stop app
trap 'docker compose -p xata start app' EXIT
docker compose -p xata cp app:/data "$xata_backup/data"
test -s "$xata_backup/data/xata.sqlite3"
)
```

Если копирование завершилось ошибкой, не продолжайте. Перенесите копию вне
сервера. Не публикуйте .env и SQLite. Затем:

```sh
(
set -eu
test -z "$(git status --porcelain --untracked-files=no)"
git switch xata/initial-app
git pull --ff-only origin xata/initial-app
docker compose -p xata config --quiet
docker compose -p xata build app
docker compose -p xata up -d --no-deps app
curl --fail --show-error --retry 15 --retry-connrefused --retry-delay 2 http://172.31.1.1:3010/healthz
docker compose -p xata ps
)
```

Проверьте старые статусы, риелторские комментарии, историю цен и фото. Назначьте
просмотр, откройте «Запланированные», запишите результат и проверьте семейный
статус. Проверьте мобильную форму и историю повторных поездок. Для отладки:
`docker compose -p xata logs --tail=80 app`.

Откат к прежнему коду допускает добавленные таблицу и поле: данные просмотров
остаются в SQLite, старый интерфейс их не показывает. Перед любым откатом
сохраните свежую копию данных. Не восстанавливайте старую БД поверх новых
решений пользователей без отдельного решения владельца. Volumes не удалять.
