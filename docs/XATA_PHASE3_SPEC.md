# XATA Phase 3 — пакет изменений для Codex

## База для работы

Репозиторий: `neofart-art/cian`  
Ветка: `xata/initial-app`

Работать поверх актуального `HEAD` ветки на момент выполнения.

**Не выполнять deployment на OMV.**  
После изменений прогнать тесты, закоммитить результат в `xata/initial-app` и сообщить SHA.

# 1. Новый логотип ХАТА

Эту задачу намеренно отложили из текущей итерации и переносим в отдельный пакет для Codex.

## Выбранная концепция

Использовать логотип в стиле:

- крупная оранжевая буква **«Х»**, одновременно формирующая силуэт крыши/дома;
- справа от верхней части «Х» — короткий вертикальный элемент, читающийся как труба/часть дома;
- под центром крыши — небольшое окно из четырёх квадратов;
- подпись **«ХАТА»** под знаком;
- первая буква **«Х»** в слове «ХАТА» — оранжевая;
- **«АТА»** — тёмно-графитовые;
- общий стиль: современный, лаконичный, без лишних деталей;
- фон логотипа должен быть прозрачным для production-asset.

Референс: выбранный пользователем оранжево-чёрный вариант из текущего обсуждения. Не использовать прежний бирюзовый вариант.

## Требования к production asset

Не встраивать изображение как огромный `data:image/...;base64` непосредственно в `index.html`.

Подготовить отдельный статический asset, предпочтительно:

```text
app/static/xata-logo.svg
```

Если SVG по технической причине не подходит, допустим оптимизированный WebP/PNG с прозрачным фоном.

Логотип должен:
- хорошо выглядеть на светлом текущем фоне XATA;
- не иметь белой прямоугольной подложки;
- оставаться читаемым при высоте 40–70 px;
- корректно масштабироваться на desktop и mobile;
- не раздувать HTML;
- не ломать CSP;
- не требовать внешних CDN/fonts/assets.

## Размещение

В верхнем левом углу страницы заменить текущую текстовую марку:

```text
ХАТА   Совместный поиск квартиры
```

на:

```text
[логотип ХАТА]   Совместный поиск квартиры
```

Подпись «Совместный поиск квартиры» сохранить.

На desktop ориентир:
- высота логотипа около 52–60 px;
- естественная ширина по пропорциям;
- вертикальное выравнивание по центру с подписью.

На мобильных:
- логотип уменьшать адаптивно;
- не допускать наложения на блок пользователя/кнопку выхода;
- при необходимости подпись можно скрывать по существующей логике.

## Favicon

Из знака логотипа сделать локальный favicon:
- использовать только символ «Х-дом/крыша» без подписи «ХАТА»;
- SVG или PNG;
- подключить в `<head>`.

## Cache busting

У проекта уже была проблема со stale static cache. Новый logo asset должен участвовать в действующей стратегии cache-busting/versioning. После deployment не должно требоваться ручное очищение кэша.

## Доступность

Для основного изображения:

```html
alt="ХАТА"
```

Если логотип обёрнут ссылкой на главную страницу, у ссылки должна быть понятная accessible name.

## Не делать

- не использовать inline base64 в HTML;
- не использовать внешние URL для логотипа;
- не использовать прошлый бирюзовый вариант;
- не менять всю цветовую схему сайта под логотип;
- не добавлять анимацию;
- не ухудшать текущую читаемость заголовка/авторизации.

## Tests / checks

Добавить или обновить проверки, которые подтверждают:
- asset существует;
- `index.html` ссылается на локальный asset;
- нет огромного inline base64 logo;
- логотип доступен HTTP 200 в тестовом приложении;
- CSP не блокирует asset;
- desktop layout не ломается;
- mobile layout не ломается;
- favicon подключён;
- существующие auth/UI тесты проходят.

# 2. Definition of Done для логотипа

Готово, когда:
- в шапке отображается именно оранжево-чёрный логотип ХАТА;
- используется отдельный локальный static asset;
- фон прозрачный;
- подпись «Совместный поиск квартиры» сохранена;
- favicon сделан из знака;
- desktop/mobile выглядят аккуратно;
- stale cache не мешает обновлению;
- полный relevant CI зелёный;
- deployment на OMV Codex самостоятельно не выполняет.

# 3. После выполнения

1. Закоммитить изменения в `xata/initial-app`.
2. Сообщить SHA.
3. Перечислить изменённые файлы.
4. Указать формат/размер logo asset.
5. Сообщить результаты тестов.
6. Дать безопасную пошаговую инструкцию обновления OMV:
   - backup SQLite;
   - backup `.env`;
   - `git pull --ff-only`;
   - config checks;
   - build только нужного `app`;
   - health check;
   - визуальная проверка desktop/mobile.
7. Deployment на OMV самостоятельно не выполнять.
