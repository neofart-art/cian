# Проверка карточек перед сохранением

## Подтверждённый дефект

На OMV объявление 333386132 впервые сохранено 15.11.2026 в 18:39:33 МСК
с `source=ЦИАН browser`, адресом в Капотне и `metro_time=10 мин. транспортом`.
Работающий app использовал новую ссылку с 53 районами и `only_foot=2&foot_min=10`.
Доказано принятие неподходящей карточки; принадлежность именно к рекомендациям
ещё не подтверждена снимком реального DOM. Прежняя проверка ограничивалась ценой.

## Поведение исправления

`app/browser_admission.py` вызывается адаптером ДО upsert. Работает также с
прежним одностраничным collector, не требуя `coverage` или новых полей ответа.

- Требует известную допустимую цену; неизвестная цена больше не проходит.
- Проверяет `mintarea`, явно распознанное число комнат, запрет первого этажа,
  минимальное число этажей ДОМА (`minfloorn`, а не этаж квартиры).
- При `only_foot=2` требует явные минуты **пешком** и проверяет лимит. Транспорт
  отклоняется даже при ошибочно заполненном `metro_walk_minutes`.
- Не допускает явные упоминания аукциона, городских/электронных торгов в видимом
  тексте карточки. Это самостоятельное правило, а не трактовка numeric-кода
  `electronic_trading=2`. Консервативная текстовая проверка может отклонить
  фразу «не аукцион»; отсутствие слов не доказывает отсутствие торгов в деталях.
- Район извлекается из явного `р-н ...`/`район ...` в адресе. Метро не считается
  районом. Неизвестный или неподтверждённый район не допускается.
- Никакой оценки людям, удаления старых квартир, изменения matcher и миграций БД.
- Частично прошедший пакет сохраняет только допущенные карточки. Если отклонён
  весь непустой пакет, запуск завершается ошибкой, не затирая last_success.

В `browser_state.coverage.admission` записываются количества received/admitted/
rejected, причины и `missing_district_names`. Одна карточка может иметь несколько
причин, поэтому сумма счётчиков причин может превышать rejected. В логах только
счётчики/коды, без URL, cookies, токенов, текстов и аккаунтов.

Лифт, ремонт, юридический тип продажи, снос и прочие условия без доступных
доказательств в карточке НЕ объявляются проверенными: соответствующие имена
параметров отражаются в `not_independently_verified`. Данные карточки остаются
заявлениями источника; это не юридическая проверка и не осмотр квартиры.

## Проверенные названия районов: обязательная подготовка

В CIAN URL числовые ID, в карточке — название. Нельзя подставлять выдуманный
словарь или считать любой неузнанный район подходящим. Перед включением строгой
проверки нужен список **названий всех выбранных районов**, подтверждённый
пользователем по фильтру ЦИАН. Порядок названий не важен, соответствие каждому
отдельному ID не требуется. Политика связывается со ВСЕМ набором ID.

Формат переменной app `CIAN_DISTRICT_POLICY` (искусственный пример,
777 НЕ является утверждением о реальном ID ЦИАН):

```json
{"ids":["777"],"names":["Тестовый"]}
```

Набор ids обязан точно совпадать с district-параметрами текущего URL, количество
уникальных непустых names — с количеством выбранных ID. Изменение набора ID
делает прежнюю политику недействительной. Пустая политика при фильтре районов
отклоняет неподтверждённые адреса; НЕЛЬЗЯ устанавливать её в production, ожидая,
что текущий набор из 53 районов начнёт автоматически пропускаться.

## Отсечение рекомендаций в DOM

`collector/page.py` отбрасывает карточки в явно обозначенных контейнерах
Recommendations/Similar/RelatedOffers и после поддерживаемых видимых заголовков
похожих предложений. Скрытые заголовки и слова внутри карточки не задают границу.
Неизвестная разметка не считается доказательством основной выдачи: второй слой
проверяет фактические поля карточки независимо от DOM.

Это ограниченная защита известных структур, а НЕ доказательство, что вся
реальная текущая разметка ЦИАН распознана. Нужен реальный DOM-тест на OMV.
