# «Все объявления» и «Наши квартиры»

Общая авторизация, SQLite и модель property. URL первой страницы — /,
второй — /ours. Обе страницы доступны по прямому адресу и после перезагрузки.
Неавторизованный запрос перенаправляется на /login, HTML/API имеют no-store.
Шапка и навигация общие; текущая страница отмечена aria-current.
Счётчик «Наши квартиры» включает все четыре группы, включая свёрнутую.

## Выбор

«В наш список» и «Убрать из нашего списка» доступны покупателям/reviewer и admin.
Сервер проверяет роль, CSRF, property_id и selection_version; устаревшая правка
получает 409. Повтор без изменения значения с актуальной версией не пишет данные.
Кнопки блокируются на время запроса, версии защищены от старых ответов polling.

Признак независим от семейной/риелторской оценки и результата поездки. Отказ
не удаляет выбранную квартиру. Явное удаление возвращает её на первую страницу,
при текущем отказе — в закрытый раздел «Не подходят», сохраняя все данные.
Перепубликация и импорт используют прежний property. При подтверждённом merge
выбор объединяется через OR, версия повышается; алгоритм matcher не изменён.

## Первая страница

Прежние 12 колонок: фото, CIAN ID, объект/адрес, цена, ипотека, площадь, этаж,
метро, до метро, добавлено, семейная оценка, риелтор с комментарием.
Только невыбранные квартиры; отказы остаются в закрытом разделе.
Поиск, CSV-предпросмотр/подтверждение, Excel и управление пользователями сохранены.
Нет календаря/результата, групп после поездки, подготовки документов, ближайших
встреч, сравнения и фильтра «Просмотренные». visits.js/compare.js здесь не загружаются.

## Вторая страница

Семь колонок: фото; квартира (ЖК/адрес/ссылка ЦИАН); цена; дата; результат;
риелтор/юрист (прежняя роль realtor); этап отбора. Отдельных колонок ипотеки,
добавления и семейного статуса нет. Площадь, этаж, метро, путь до метро,
публикации и цены находятся в раскрываемых «Характеристиках».

Группы и счётчики уникальных property:
- «К просмотру»: нет однозначного последнего результата, нейтральный фон;
- «Оставляем в запасе»: liked, голубой;
- «Проверка документов»: liked и прежняя подготовка документов, зелёный;
- «Не понравилось»: rejected, красный, закрыта по умолчанию.
Остальные открыты. Цвет дополнен текстом и полосой слева. Отказ риелтора
показывается красной меткой отдельно, не подменяя цвет группы покупателей.

Этап — select двух положительных значений; редактируют семья/admin, риелтор читает.
Используется прежний PATCH viewing-classification и visits_version.
Это начало проверки документов, а не подтверждение юридической чистоты.
Даты/заметки/обычное обновление и повторный положительный результат не сбрасывают
этап. Исправление актуального отрицательного результата на положительный начинает
с запаса. Учитывается последний completed по фактической дате, не новая встреча.
thinking сохраняется в «К просмотру» с меткой «Думаем — уточните результат».

Календарь прежний: ДД.ММ.ГГГГ, значок, месяцы, черновик, «Очистить»/«ОК»;
change/blur не сохраняют, polling не сбрасывает черновик. Только realtor/admin
меняют inline-дату. Права и даты внутри формы результата остаются прежними.
Сортировка по показанной московской дате, неизвестные значения в конце.
Состоявшуюся дату нельзя удалить; очистка planned отменяет встречу, сохраняя историю.

Кнопка результата открывает прежнюю форму с двумя результатами, комментарием,
причинами, историей/повторными поездками и защитой от конфликтов.
**Заметка до поездки убрана из формы, истории на экране и ближайших встреч.**
preparation остаётся в SQLite/API/XLSX; при редактировании старого просмотра форма
отправляет прежнее значение, чтобы невидимое поле не стиралось.

Ближайшие встречи и сравнение существуют только здесь, для выбранных квартир.
Ближайшие включают повторы/просроченные/отказанные, сегодня не просрочено.
Сравнение 2–4 сохраняет прежние ограничения и ипотечную формулу. После удаления
из нашего списка квартира исключается из текущего сравнения с сообщением.
Никакой автоматический рейтинг не добавлен.

## Additive миграция

Через существующий migrate_viewings добавляются два поля properties:
- in_our_list INTEGER NOT NULL DEFAULT 0 CHECK(in_our_list IN (0,1));
- selection_version INTEGER NOT NULL DEFAULT 0.

В существующей транзакции app/migrations.py маркер our_list_initial_selection_v1
один раз включает property с любыми существующими property_visits, включая
cancelled и thinking. Только семейный liked без просмотров не выбирает квартиру.
Повтор запуска не выбирает заново вручную удалённые квартиры.
История, этап документов, сторонние столбцы/BLOB/индексы/триггеры и сессии сохранены.
Таблицы не пересоздаются, записанные результаты не преобразуются.

API state/listing добавляет in_our_list и selection_version.
PATCH /api/listings/{id}/selection:
{property_id, selection_version, selected: true|false}.
Прежние endpoints просмотров/оценок/импорта совместимы.
В XLSX в конец «Объявления» добавлен «В нашем списке», названия групп обновлены.
Прежние столбцы и лист «Просмотры» с обеими заметками сохранены.

## Обновление OMV владельцем

Пересобрать только app. Browser, NPM, порт 3010, .env и persistent volumes прежние.
Используйте существующий каталог проекта и project xata. Завершите сбор,
отключите временный noVNC, не редактируйте данные во время backup/обновления.

Проверьте git status --short и volume xata_xata_data:/data.
Не затирайте локальные изменения. До git pull:

~~~sh
(
set -eu
umask 077
xata_backup="backups/xata-before-two-pages-$(date -u +%Y%m%dT%H%M%SZ)"
mkdir -p "$xata_backup"
git rev-parse HEAD > "$xata_backup/git.sha"
cp .env "$xata_backup/.env"
docker compose -p xata stop app
trap 'docker compose -p xata start app' EXIT
docker compose -p xata cp app:/data "$xata_backup/data"
test -s "$xata_backup/data/xata.sqlite3"
echo "Backup: $xata_backup"
)
~~~

При ошибке backup не продолжать. Сохраните копию вне сервера, не публикуйте .env/SQLite.
После успешного полного CI:

~~~sh
(
set -eu
test -z "$(git status --porcelain --untracked-files=no)"
git switch xata/initial-app
git pull --ff-only origin xata/initial-app
docker compose -p xata config --quiet
docker compose -p xata build app
docker compose -p xata up -d --no-deps app
curl --fail --show-error --retry 15 --retry-connrefused --retry-delay 2 http://172.31.1.1:3010/healthz
docker compose -p xata ps
)
~~~

Перезагрузите страницу, проверьте обе вкладки, старые просмотры и этапы, календарь,
форму, фотографии, CSV, сравнение и ближайшие встречи.
Логи: docker compose -p xata logs --tail=80 app.
Не применять down -v/volume prune/очистку SQLite/профиля.
Откат: сначала свежий backup /data, затем app из сохранённого SHA. Новые поля
additive; старую БД поверх новых пользовательских решений не восстанавливать.
Deployment на OMV из среды разработки не выполняется.
