# Одно заглавное фото объявления

В общем списке первая колонка «Фото» постоянно показывает миниатюру 110×80 px,
с lazy loading и object-fit: cover. При отсутствии/ошибке изображения остаётся
placeholder «Нет фото». Нажатие открывает то же фото крупнее в диалоге с адресом,
ценой и ссылкой ЦИАН. Отдельной страницы подробной карточки в текущем XATA нет;
диалог не содержит галереи. Таблица сохраняет прежние характеристики, оценки семьи
и риелтора, ручные решения по дублям и блок «Публикации и цены».

Авторское «Текст карточки / описание» больше не создаётся в DOM таблицы и диалога.
description/card_text по-прежнему собираются, хранятся, доступны backend/matcher
и диагностическому XLSX. Старые тексты и внутреннее сопоставление не меняются.

## Откуда берётся фото

collector/page.py расширяет прежний атомарный snapshot rendered DOM карточек
(максимум 100). Внутри видимой карточки выбирается первое видимое изображение
в ссылке /sale/flat/, Gallery или OfferImage; аватары/информация продавца
исключаются. Берётся currentSrc, либо src уже отображаемого img. Скрытые слайды,
srcset, embedded state, cookies, токены и API не читаются. Дополнительного перехода
в объявление/галерею нет. CAPTCHA/login/readiness/profile остаются прежними.
Если селектор или CDN на реальном ЦИАН изменились, фото останется необязательным.

После сохранения объявлений основной app скачивает только этот файл с
https://images.cdn-cian.ru. Запрос не использует браузерные credentials/cookies.
Другие хосты/схемы/порты/redirects не разрешены. DNS проверяется на публичные IP,
соединение закрепляется за проверенным адресом с обычной проверкой TLS hostname.
Загрузка ограничена 6 MiB и короткими сетевыми timeout; body deadline — 6 секунд.
Допустимы JPEG/PNG/WebP/AVIF, один кадр и не более 16 миллионов пикселей.
HTML/SVG/неподдерживаемые данные отклоняются. В логах только ID, тип ошибки,
при наличии HTTP status, без URL/query/cookies/содержимого изображения.

## Данные и локальные файлы

Существующий migrate_listings добавляет к listings четыре nullable TEXT-колонки,
только если их ещё нет:

| Поле | Назначение |
| --- | --- |
| cover_image_url | Последний допустимый URL главного фото из DOM |
| cover_image_path | Относительный путь к нормализованной локальной JPEG-копии |
| cover_thumb_path | Относительный путь к миниатюре того же фото |
| cover_image_cached_url | URL, для которого успешно сохранена текущая пара файлов |

Таблицы не пересоздаются, существующие поля/неизвестные столбцы и first_seen
сохраняются. Повторный запуск миграции безопасен. У старых записей новые поля NULL;
они работают с placeholder и получают фото при следующем обычном обновлении.
Автоматической массовой загрузки при запуске/миграции нет.

Каталог: DATA_DIR/images/listings (в Docker /data/images/listings, существующий
named volume xata_xata_data). Имена: ID-<хеш содержимого>-normal.jpg и
ID-<тот же хеш>-thumb.jpg. Нормальная копия ограничена 1600×1200, миниатюра —
220×160 для отображения 110×80; metadata удаляются. Многомегабайтный оригинал
и другие фотографии объявления не сохраняются. На объединённый объект хранится
одна рабочая пара файлов; при перепубликации допускается повторное использование
той же фотографии без сетевого скачивания. Старые файлы удаляются только после
успешной записи новой пары в БД. Дисковое место растёт с числом объектов;
изображения стоит включать в резервные копии существующего /data.

Один фоновый worker app с ограниченной очередью 500 выполняет изображения
после commit импорта, вне writer-транзакции SQLite. Предпросмотр CSV не скачивает
фото и не ставит jobs. CSV не требует сетевого доступа для сохранения объявлений;
после подтверждения он может восстановить отсутствующую локальную копию по ранее
сохранённому URL. Обычный CSV без такого URL продолжает работать как прежде.
Переполнение очереди/ошибка скачивания/декодирования/диска не меняет успешный
результат импорта; следующая обычная обработка объявления повторит попытку.

Если URL прежний и оба файла существуют, скачивание/перезапись не выполняются.
Если файл отсутствует или URL изменился — готовится новая пара. При ошибке
остаются прежние рабочие пути и файлы. Перед записью проверяется актуальность
URL и привязки публикации, чтобы устаревшая загрузка не перезаписала новые данные.

Файлы выдаются только авторизованным пользователям через
/api/listings/{id}/cover/{content_hash}/{normal|thumb}; произвольных путей/URL
и публичного монтирования /data нет. API состояния добавляет локальные
cover_image_src/cover_thumb_src. Хеш в URL меняется с содержимым; существующий
asset cache busting JS/CSS также остаётся. Для открытого списка новое фото
появляется при штатном обновлении состояния.

## Безопасное обновление OMV

Эти команды выполняет владелец. Codex не выполняет deployment. Используйте
прежний каталог проекта, .env и проект xata. Не меняйте NPM, порт 3010,
xata_xata_data, xata_browser_profile и другие Docker-проекты. Временный noVNC
должен быть выключен, сбор — завершён.

1. Проверьте git status, ветку и mounts:

~~~sh
git status --short
git branch --show-current
docker inspect "$(docker compose -p xata ps -q app)" --format '{{range .Mounts}}{{println .Name .Destination}}{{end}}'
docker inspect "$(docker compose -p xata ps -q browser)" --format '{{range .Mounts}}{{println .Name .Destination}}{{end}}'
~~~

Ожидаются xata_xata_data:/data и xata_browser_profile:/profile. Несвязанные
локальные изменения сначала сохраните; не используйте reset --hard.

2. Согласованная резервная копия до обновления:

~~~sh
umask 077
mkdir -p backups
xata_stamp="$(date -u +%Y%m%dT%H%M%SZ)"
git rev-parse HEAD > "backups/xata-before-covers-$xata_stamp.sha"
cp .env "backups/xata-before-covers-$xata_stamp.env"
docker compose -p xata stop app
docker compose -p xata cp app:/data/xata.sqlite3 "backups/xata-before-covers-$xata_stamp.sqlite3"
~~~

При неудачном копировании не продолжайте обновление: запустите прежний app и
устраните причину. Если /data/images уже существует, при остановленном app
скопируйте его отдельно:

~~~sh
docker compose -p xata cp app:/data/images "backups/xata-before-covers-$xata_stamp-images"
~~~

При первом обновлении этого каталога может ещё не быть — это нормально.
Запустите прежний app, проверьте размер SQLite backup; храните .env/БД вне
публичного доступа и перенесите копию вне сервера.

~~~sh
docker compose -p xata start app
~~~

3. Получите изменения, проверьте compose без вывода секретов и соберите **оба**
образа: изменились app и DOM extractor в browser.

~~~sh
git switch xata/initial-app
git pull --ff-only origin xata/initial-app
docker compose -p xata config --quiet
docker compose -p xata -f docker-compose.yml -f docker-compose.browser-login.yml config --quiet
docker compose -p xata build app browser
docker compose -p xata stop app
docker compose -p xata up -d --no-deps browser
docker compose -p xata up -d --no-deps app
docker compose -p xata ps
curl --fail http://172.31.1.1:3010/healthz
~~~

Первый старт выполняет только additive SQLite migration; фото не скачиваются
массово. Профиль браузера и авторизация остаются в прежнем volume. Убедитесь,
что оба сервиса healthy. Не используйте down -v, volume prune или очистку профиля.

4. Откройте XATA, проверьте сохранность объектов/first_seen, статусов семьи,
решений/комментариев риелтора, ручных решений по дублям и истории цен. Старые
объекты без фото должны отображать placeholder. Под администратором запустите
обычный browser search, затем дождитесь фоновых файлов и обновления списка.
Проверьте фото, увеличение, отсутствие авторского текста, «Публикации и цены»,
CSV preview/confirm и XLSX. Реальный selector/CDN ЦИАН и поведение на OMV
подтверждаются только этой проверкой владельцем.

Откат к коду до этого изменения совместим с добавленными nullable-столбцами.
Сначала сохраните текущую БД, остановите app, вернитесь к записанному прежнему
SHA, пересоберите app/browser и запустите только эти сервисы с теми же volumes.
Если требуется полное восстановление backup, согласуйте БД и каталог изображений;
оно потеряет последующие изменения, поэтому сохраните их копию. Права /data
должны оставаться у UID/GID 10001. Не удаляйте persistent volumes.

## Проверки

Используется существующий полный XATA checks: pytest, Node regressions,
обе Compose-конфигурации, JavaScript syntax, offline Chromium DOM/UI, сборка
обоих Docker-образов, healthcheck и временный noVNC с сохранением профиля.
tests/test_covers.py проверяет миграцию, локальные варианты, отсутствие повторных
загрузок, смену/пропажу/ошибки фото, stale jobs, перепубликации, CSV commit,
ограничения источника/размера и защищённую выдачу. UI-тесты проверяют постоянно
видимую колонку, placeholder, lazy loading, диалог, отсутствие авторского текста,
историю и сохранение статуса. Тестовые страницы/изображения локальные,
без реального ЦИАН. Успешный CI не подтверждает работу с реальным ЦИАН или OMV.
