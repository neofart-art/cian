# Просмотренные квартиры

Три группы под основным списком:
- «Понравилось — пока без проверки документов»: открыта, голубые строки;
- «Понравилось — готовимся к проверке документов»: открыта, зелёные строки;
- «Не понравилось»: закрыта, красные строки.

Каждая группа показывает число property, а не CIAN ID. Цвет дополняют текстовая
метка в строке и цветная полоса слева. Риелторский отказ показывается явной красной
меткой «Отбраковано риелтором», сохраняя цвет группы покупателей.

## Правила и совместимость

Основание — последний completed по completed_at, при равной дате — больший ID.
Семейное мнение по объявлению и независимая оценка риелтора не определяют эту группу.
Строка property переносится между взаимоисключающими tbody; фото, публикации/цены,
комментарии, история и черновики остаются в прежнем компоненте. Квартира не
дублируется в основном списке и «Не подходят». Ближайшие встречи остаются отдельным
представлением встреч, включая повторные встречи с уже просмотренными квартирами.

Существующие liked/rejected распределяются сразу, без изменения исторических записей.
**Прежний thinking («Думаем») не преобразуется.** Если он является последним
результатом, показывается предупреждение с количеством, квартира остаётся в прежнем
разделе с меткой «Думаем — группа не выбрана». Для новой классификации покупатель
или администратор должен явно исправить результат существующей формой. Более старые
thinking сохраняются в истории и не подменяют более поздний однозначный результат.

Кнопка в положительной строке переводит между двумя положительными группами.
Покупатели/reviewer и admin могут менять подготовку документов, realtor только
читает. Сервер проверяет роль, CSRF, property_id и visits_version. Конфликт — 409
без перезаписи чужого изменения. Подготовка не меняет просмотры или оценки.
Редактирование комментария, заметок и дат не сбрасывает подготовку. Дата может
изменить, какой просмотр последний, но само поле подготовки при этом сохраняется.
Повторный положительный просмотр сохраняет выбранную подготовку.

Новый отрицательный результат по-прежнему атомарно меняет семейную оценку на
«Не подходит». Исправление актуального отрицательного результата на положительный
начинает группу «пока без проверки документов». Изменение более старого результата
не перекрывает более поздний и не сбрасывает его подготовку. История не удаляется.

Отказы без однозначного состоявшегося просмотра остаются в «Не подходят».
Возврат через оценку объявления не удаляет фактический результат поездки.
Форма результата, её даты/права, inline календарь с «ОК», расписание, collector,
matcher и формула ипотеки не менялись. При подтверждённом merge подготовка
наследуется от property, которому принадлежит последний состоявшийся просмотр;
вся история обеих квартир сохраняется. Сравнение остаётся доступным положительным
просмотренным квартирам по прежним правилам; отрицательные результаты исключаются,
как и действующий отказ семьи/риелтора. Выбор для сравнения ничего не сохраняет.

## Миграция и API

Идемпотентный ALTER TABLE через существующий app/viewings.py:migrate:
properties.viewing_documents_ready INTEGER NOT NULL DEFAULT 0 CHECK(... IN (0,1)).
Нет новых таблиц, удаления/пересоздания БД или переписывания старых результатов.
SQLite применяет добавление внутри существующей транзакции миграций.
Старые поля, сторонние столбцы/BLOB/индексы/триггеры, сессии и записи сохраняются.

Используется прежний visits_version property; он повышается также при смене группы.
API state/listing добавляет viewing_documents_ready (bool) и viewed_group
(null | liked | documents | rejected). viewed_group вычисляется по истории.
PATCH /api/listings/{id}/viewing-classification:
{property_id, visits_version, documents_ready: true|false}.
Разрешён только при актуальном положительном результате, значения boolean строгие.
API не принимает результат, даты или риелторскую оценку в этом запросе.

К существующему XLSX в конец листа «Объявления» добавлена «Группа после просмотра».
Прежние листы, столбцы и история просмотров сохранены. Кеширование CSS/JS использует
существующие хеши содержимого, ручной сброс кеша не требуется.

## Проверки

tests/test_viewed_groups.py: старая production-подобная SQLite, идемпотентность,
сессии/история/сторонние поля, переходы, даты/старые результаты, роли и CSRF,
конкурентные изменения, reload, merge в обоих направлениях, импорт, перепубликация,
цены и XLSX. tests/review_state.test.cjs: взаимоисключающие разделы, stale responses,
сортировка/сравнение. tests/test_ui.py: desktop и touch/mobile Chromium, реальные
кнопки и форма, цвета/метки/полоса, независимый отказ риелтора, предупреждение
thinking, счётчики, отсутствие повторных property, polling/reload, ближайшие встречи
и горизонтальная прокрутка внутри таблиц.

Полный XATA checks запускается в GitHub Actions: Python/Node/Chromium, Compose,
обе Docker-сборки, timezone check, browser health и noVNC/profile smoke.
Это offline-проверки; настоящий ЦИАН, физический телефон и OMV не проверяются.

## Безопасное обновление OMV

Изменён только app, browser пересобирать не нужно. Работайте в прежнем каталоге
проекта с прежним .env и project xata. Закончите поиск, выключите временный noVNC,
попросите пользователей не вносить правки во время резервного копирования.
Проверьте git status и volumes: xata_xata_data:/data, xata_browser_profile:/profile.
Несвязанные локальные изменения сохраните, не применяйте reset --hard.

Согласованная резервная копия до git pull:

~~~sh
(
set -eu
umask 077
xata_backup="backups/xata-before-viewed-groups-$(date -u +%Y%m%dT%H%M%SZ)"
mkdir -p "$xata_backup"
git rev-parse HEAD > "$xata_backup/git.sha"
cp .env "$xata_backup/.env"
docker compose -p xata stop app
trap 'docker compose -p xata start app' EXIT
docker compose -p xata cp app:/data "$xata_backup/data"
test -s "$xata_backup/data/xata.sqlite3"
echo "Backup: $xata_backup"
)
~~~

Если копирование завершилось ошибкой, обновление не продолжать. Храните копию вне
сервера; .env и база содержат закрытые данные.

После успешного полного CI:

~~~sh
(
set -eu
test -z "$(git status --porcelain --untracked-files=no)"
git switch xata/initial-app
git pull --ff-only origin xata/initial-app
docker compose -p xata config --quiet
docker compose -p xata build app
docker compose -p xata up -d --no-deps app
curl --fail --show-error --retry 15 --retry-connrefused --retry-delay 2 http://172.31.1.1:3010/healthz
docker compose -p xata ps
)
~~~

Обновите страницу; проверьте группы и предупреждение thinking, переходы, календарь,
результаты/историю, фото, риелторскую оценку, ближайшие встречи и сравнение.
Логи: docker compose -p xata logs --tail=80 app.

Нельзя удалять volumes, использовать down -v, volume prune или сбрасывать SQLite.
Для отката сначала сделайте свежую копию /data, затем соберите app из SHA в backup.
Добавочное поле совместимо с предыдущей версией; возвращать старую БД поверх новых
семейных решений нельзя без явного решения владельца. Порт 3010, NPM, основной сайт,
browser profile и другие проекты не затрагиваются. Deployment выполняет владелец.
