# Хата — личный поиск квартир

Лёгкое приложение для Debian 13 / OMV: FastAPI, статический интерфейс и SQLite в одном контейнере. Отдельные Node.js, Redis, PostgreSQL не нужны. Домен: `https://xata.neofart.ru`, задаётся через `PUBLIC_URL`.

## Что реализовано и что ещё не подтверждено

Фильтры по умолчанию: Москва, покупка, вторичка, одна комната, до 14 млн ₽, до метро 20 минут пешком. Цена и минуты редактируются. Интерфейс показывает историю объявлений, статус последнего запуска и экспортирует XLSX. Это ручной сбор одной страницы, без расписания и обхода защиты.

**Реальный сбор не подтверждён:** при проверке из среды разработки Циан ответил перенаправлением на `/tmgrdfrend/showcaptcha`. Приложение останавливается при таком ответе. Источник `app/source.py` поддерживает публичные JSON-LD `Apartment`/`Product`/`RealEstateListing` с ценой и ссылкой объявления. Совместимость этого формата с текущей выдачей Циан не подтверждена. Если сайт не отдаёт такой формат, сбор завершится явной ошибкой; потребуется адаптировать модуль к разрешённому источнику данных. Наличие рабочего интерфейса не означает, что сбор уже работает.

Параметры вторички, комнаты и метро передаются в URL поиска; их применение сайтом не подтверждено и не проверяется независимо парсером. Цена дополнительно проверяется локально. Поля площади, этажа, метро и описания пока не извлекаются. Проверяйте характеристики в оригинале. Сохранённые строки — история, а не гарантированно актуальные предложения; старые объявления не удаляются. XLSX включает всю историю.

## Запуск на OMV

Используйте отдельную директорию, например `/opt/xata`. Не меняйте существующие compose-проекты и NPM. Команды ниже выполняются из директории этого проекта.

1. Скопируйте `.env.example` в `.env`, задайте свой `APP_USER` и уникальный `APP_PASSWORD` длиной от 16 символов. Не публикуйте `.env`. Для генерации пароля можно использовать `openssl rand -hex 24` локально на сервере.
2. Проверьте адрес: `ip -brief address`. IP `172.31.1.1` должен принадлежать хосту OMV и быть доступен из контейнера NPM. Проверьте, что порт не занят: `ss -ltn '( sport = :3010 )'`. При необходимости измените `BIND_IP` в `.env` на внутренний адрес сервера. Не используйте `0.0.0.0` и не создавайте проброс порта 3010 на маршрутизаторе. IP-привязка не заменяет firewall: проверьте правила OMV, Docker и маршрутизатора.
3. Запустите:

   ```sh
   docker compose -p xata config --quiet
   docker compose -p xata up -d --build
   docker compose -p xata ps
   curl --fail http://172.31.1.1:3010/healthz
   ```

4. В **Nginx Proxy Manager** создайте отдельный Proxy Host: домен `xata.neofart.ru`, Scheme `http`, Forward Hostname/IP `172.31.1.1`, Forward Port `3010`. Включите сертификат Let's Encrypt и Force SSL. Basic Auth приложения передаётся обычным заголовком Authorization; не настраивайте второй Basic Auth NPM поверх него. Само приложение слушает `0.0.0.0:8000` **в контейнере**, на хосте порт публикуется только на `BIND_IP:APP_PORT`.
5. DNS A должен указывать на внешний адрес вашего сервера; AAAA добавляйте только при рабочем IPv6. Доступ из интернета идёт через существующие порты NPM 80/443. При CGNAT одного DNS недостаточно.
6. Откройте домен, войдите с данными из `.env`, запустите сбор. При CAPTCHA/HTTP-ошибке прочтите статус и `docker compose -p xata logs --tail=100 app`. Не обходите ограничения Циан.

Контейнер работает от UID/GID 10001, с read-only корневой системой, временным `/tmp`, лимитами 384 МБ и одного CPU. SQLite хранится в named volume `xata_xata_data` при использовании `-p xata`. `docker compose down` сохраняет данные; **`down -v` удаляет базу**. Не подменяйте named volume каталогом OMV без подготовки прав UID/GID 10001.

### Резервная копия и обновление

Для согласованной копии остановите только этот сервис:

```sh
mkdir -p backups
docker compose -p xata stop app
docker compose -p xata cp app:/data/xata.sqlite3 ./backups/xata.sqlite3
docker compose -p xata start app
```

Сохраните резервную копию вне сервера. Для обновления файлов проекта: резервная копия, затем `docker compose -p xata up -d --build`. Существующие сервисы эти команды не затрагивают.

### Диагностика

- Unhealthy: проверьте журналы и доступ на запись к `/data`.
- HTTP 503: задайте имя и пароль от 16 символов в `.env`, пересоздайте контейнер через `up -d`.
- HTTP 403 при нажатии сбора: `PUBLIC_URL` должен точно совпадать с HTTPS-адресом в браузере, без пути.
- HTTP 429: минимальный интервал между запусками 60 секунд.
- HTTP 302/CAPTCHA/нет поддерживаемых данных: сбор остановлен; прежние данные остаются. Нужна проверка разрешённого источника, а не обход защиты.

`/healthz` проверяет приложение и доступ к SQLite, а не доступность Циан. Журналы Docker ограничены 3 файлами по 5 МБ. История SQLite пока не очищается автоматически. Один Uvicorn worker обязателен для блокировки одновременного сбора.

## Локальная разработка

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/pip install pytest==8.3.5
.venv/bin/python -m pytest -q
```

Для запуска задайте `APP_USER`, `APP_PASSWORD`, необязательно `DATA_DIR` и `PUBLIC_URL`, затем `.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000`. Секреты задавайте локально, не сохраняйте в Git. `PUBLIC_URL` для локального HTTP можно не задавать. Тесты используют временную БД и искусственный JSON-LD, не являются проверкой реальной выдачи Циан.
