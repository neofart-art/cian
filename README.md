# ХАТА — совместный выбор квартиры

FastAPI + SQLite + статический интерфейс; отдельный browser service с обычным Playwright/Chromium. Домен: https://xata.neofart.ru. CSV остаётся независимым резервным импортом.

По сообщению владельца, browser collector и сохранённая сессия ЦИАН уже работают на OMV. В Phase 2 в collector изменена только нормализация metro_time: generic TimeLabel принимается лишь как явная длительность пути. Snapshot/CAPTCHA/login, профиль, noVNC, navigation, cadence расписания, browser API token, Docker Compose и ограничения browser image не меняются. CI использует искусственные страницы; реальный ЦИАН в этой среде не проверяется.

## Пользователи и просмотр объявлений

XATA использует обычную страницу /login, SQLite users и серверные сессии вместо HTTP Basic. При первом запуске с пустой users создаётся администратор из существующих APP_USER / APP_PASSWORD (пароль от 16 символов). Миграция повторяема, уже созданный пользователь не перезаписывается значениями .env. Логин регистронезависимый, крайние пробелы игнорируются.

Откройте «Пользователи» под таблицей: создайте отдельные аккаунты для семьи и риелтора. Роль **«Просмотр»** читает объявления и меняет общий семейный статус. Роль **«Риелтор»** видит общий статус, но меняет только отдельную оценку и комментарий риелтора. Семья читает мнение риелтора без возможности редактирования. **Администратор** может менять обе оценки независимо. Только **администратор** запускает сбор, видит состояние browser collector, импортирует CSV, экспортирует XLSX и управляет пользователями. Ограничения проверяются сервером, включая прямые API-запросы. Аккаунты отключаются вместо удаления; последнего активного администратора нельзя отключить или перевести в роль просмотра.

Пароли хешируются Argon2id (19 МиБ, 2 прохода, parallelism 1). Сессионная cookie __Host-xata_session — Secure, HttpOnly, SameSite=Lax, Path=/, срок 7 дней; в БД хранится только SHA-256 случайного идентификатора сессии. Выход отзывает текущую сессию. Отключение пользователя или смена его пароля отзывает все его сессии. Роли и enabled читаются из БД при каждом запросе. Ограничение неудачных входов — 20 за 15 минут на адрес приложения; за NPM этот адрес может быть общим для посетителей. Пароли, хеши, session/CSRF/cookies не логируются и не возвращаются в API.

Вход и все изменения защищены CSRF-токенами; проверки Origin / Sec-Fetch-Site и CSP сохранены. JavaScript получает CSRF через /api/auth/csrf перед входом и /api/auth/me после входа. Секреты не сохраняются в localStorage/sessionStorage. Для входа требуется **HTTPS**: за существующим NPM Secure-cookie работает штатно, порт и настройки proxy не меняются. В локальных API-тестах используется HTTPS TestClient; для ручной локальной разработки настройте локальный HTTPS, не отключайте Secure.

Таблица использует ширину рабочего стола, Первый столбец — заглавное фото; ID ЦИАН — ссылка во втором столбце. Статусы **НОВОЕ / Понравилось / Просмотрено / Не подходит** — общий семейный выбор. «Не подходит» выделено бледно-красным, «Понравилось» — салатовым, у всех состояний есть текстовая метка. Оценка риелтора **Не оценено / Одобрено / Отбраковано** и plain-text комментарий до 2000 символов независимы от семейного статуса; комментарий раскрывается целиком. Рядом видны последний автор и время; даты в БД — UTC, в интерфейсе — часовой пояс браузера. В основном списке сначала новые, затем понравившиеся и просмотренные; внутри группы новые first_seen выше. Отказы семьи или риелтора вынесены в закрытый раздел «Не подходят» под таблицей. Фильтры со счётчиками и сортировка заголовков работают по уже загруженным данным. Клик по заголовку: возрастание → убывание → стандартный порядок. Числа, дата, этаж и минуты сортируются по смыслу; неизвестные числовые значения всегда последние. Статусы не стираются сборщиком/CSV. Версии review_version и realtor_version независимо защищают UI от устаревшего ответа автообновления; несохранённый текст риелтора также не сбрасывается при обновлении. Источник, last_seen и last_imported остаются в SQLite/API/XLSX, но не занимают столбцы экранной таблицы.

Пароли reviewer/realtor — от 8 символов, создаваемого/изменяемого admin — от 12, bootstrap — по-прежнему от 16. Argon2id не ослаблен. Повышение в admin с коротким паролем запрещено: задайте в том же действии пароль от 12 символов. Для прежнего пользователя длина хеша неизвестна, поэтому повышение тоже требует нового пароля; обычный вход и прежние admin-пароли не требуют принудительной смены.

Миграции выполняются автоматически, без ручного SQL. SQLite не умеет расширять CHECK: users и listings при старых ограничениях перестраиваются в транзакции с копированием всех существующих столбцов и значений, восстановлением индексов/триггеров и foreign_key_check. CHECK расширяется до realtor / liked соответственно. ID, first_seen/last_seen, review author/time/version, текущие users/password hashes/sessions, runs/browser_state/import_previews сохраняются. Добавляются realtor_status (pending), realtor_comment (пусто), realtor_updated_at/by (users.id), realtor_version и служебный password_length (только подтверждённый порог до 12; NULL для старых хешей, не возвращается в API). Одноразовая миграция phase2_metro_cleanup в schema_migrations исправляет только metro_time со «сегодня/вчера/назад»: повторно разбирает card_text либо очищает время и walking minutes. Корректные значения не меняются. Переименование пользователя сохраняет ID автора обеих оценок.

Верх страницы показывает read-only критерии и browser_state.last_success для всех ролей. Reviewer/realtor не получают browser errors или служебное состояние. Ипотека рассчитывается из текущей цены: взнос 6 000 000 ₽, 18% годовых, 180 месяцев, аннуитет, без страховки/комиссий/допуслуг. NULL-цена → «—», цена ≤6 млн → 0; UI округляет до 100 ₽, сортировка и XLSX используют точный расчёт. После обновления цены расчёт меняется автоматически.

HTML/API имеют Cache-Control: no-store; HTML ссылается на JS/CSS по URL с SHA-256-версией содержимого. Для static дополнительно no-cache, must-revalidate и ETag/Last-Modified: после обновления ручная очистка кэша не требуется.


APP_USER/APP_PASSWORD остаются в вашем .env для безопасного bootstrap и существующего fallback внутреннего browser API. После bootstrap они **не являются паролем входа XATA**: меняйте пароли через панель пользователей. Смена пароля XATA не меняет пароль ЦИАН и BROWSER_API_TOKEN. Не меняйте существующие значения .env вслепую: при пустом BROWSER_API_TOKEN APP_PASSWORD по-прежнему нужен обоим сервисам для внутренней связи.


## Phase 3: квартиры, публикации и ручные решения

Одна строка таблицы — один property (реальная квартира), CIAN ID — публикация внутри него. Старые ID/first_seen/last_seen сохраняются. Текущая публикация выбирается при обнаружении новой перепубликации; обновление старого ID не делает его снова текущим. «Историческая» не означает доказанное снятие с ЦИАН. В раскрываемых деталях показаны даты публикаций и история наблюдений цены, в XLSX — те же данные и диапазон цен.

Автоматическое совпадение требует полного точного адреса с домом/корпусом, близкой площади, этажа и содержательного похожего описания. Типовая реклама или совпадение полей карточки не являются независимым доказательством. Конкурирующие кандидаты и одновременно встреченные старый/новый ID требуют подтверждения. Проценты — эвристический score, не гарантия идентичности. Фото/seller matching не включены.

«Да, тот же объект» / «Нет, другая квартира» доступны admin/reviewer; realtor только читает. Решение относится к конкретному показанному кандидату. При устаревшем предложении сервер возвращает 409: обновите список. Отказ сохраняется на стабильных CIAN ID и не теряется после объединения других групп. Известные разные квартиры нельзя связать через промежуточную группу.

Семейная и риелторская оценки независимы. При перепубликации они наследуются. При ручном объединении двух оценённых групп для каждой оценки выбирается последнее действие по UTC; версии увеличиваются, обе прежние версии сохраняются в property_merge_audit. Входящий refresh не сбрасывает только что сохранённые данные. Черновик риелтора сохраняется при смене текущего CIAN ID.

Миграция не объединяет старые production-строки по предположению: каждому непривязанному listing создаётся свой property без изменения прежних оценок. Уже существующие Phase 3 группы/решения остаются. Добавляются указатель текущей публикации, алиасы объединённых property, identity_decisions, listing_price_state, property_merge_audit и property_state. Цены фиксируются при реальном изменении конкретного CIAN ID; повторные неизменившиеся публикации не создают ложные события. Первичная цена старой строки привязана к last_seen, а не выдуманной истории с first_seen.

Полный обзор найденных дефектов, исправлений и ограничений: docs/XATA_PHASE3_REVIEW.md. Если прежняя версия уже потеряла оценки/решения на OMV, восстановить их можно только из прежнего backup; новая миграция не угадывает утраченные значения.

## Безопасное обновление OMV — Phase 3

Для обновления со стабильного 472e7fd или более нового Phase 3 **нужен только app**. Browser, его image/профиль, noVNC, Compose и cadence не меняются. Ниже команды выполняет владелец; Codex deployment не выполняет.

1. В прежнем каталоге проекта проверьте git status, текущий SHA и проект xata. Убедитесь, что /data использует xata_xata_data, browser — xata_browser_profile. Дождитесь окончания текущего сбора.

2. До git pull создайте защищённые backups SQLite и .env:

~~~sh
umask 077
mkdir -p backups
xata_stamp="$(date -u +%Y%m%dT%H%M%SZ)"
git rev-parse HEAD > "backups/xata-before-phase3-$xata_stamp.sha"
cp .env "backups/xata-before-phase3-$xata_stamp.env"
chmod 600 "backups/xata-before-phase3-$xata_stamp.env"
docker compose -p xata stop app
docker compose -p xata cp app:/data/xata.sqlite3 "backups/xata-before-phase3-$xata_stamp.sqlite3"
chmod 600 "backups/xata-before-phase3-$xata_stamp.sqlite3"
docker compose -p xata start app
~~~

Если копирование не удалось, запустите прежний app и остановите процедуру обновления. Проверьте копию, сохраните backup вне сервера безопасным способом; не добавляйте backups в Git. БД и .env содержат секреты.

3. Получите изменения, проверьте конфигурацию и пересоберите только app:

~~~sh
git switch xata/initial-app
git pull --ff-only origin xata/initial-app
docker compose -p xata config --quiet
docker compose -p xata -f docker-compose.yml -f docker-compose.browser-login.yml config --quiet
docker compose -p xata build app
docker compose -p xata up -d --no-deps app
docker compose -p xata ps
curl --fail http://172.31.1.1:3010/healthz
~~~

4. Проверьте обычным обновлением страницы logo/favicon без очистки кэша, desktop/mobile, прежние аккаунты и сохранность оценок/дат. Проверьте ручной отказ/подтверждение дубля, независимые права realtor, историю цен/публикаций, CSV preview/confirm и XLSX. Browser-поиск на настоящем ЦИАН проверьте на OMV; в CI используются только искусственные данные. Не включайте noVNC для этого обновления.

5. Для отката сначала сохраните копию уже обновлённой БД, остановите только app и используйте прежний SHA/согласованный pre-upgrade SQLite backup с тем же volume и владельцем UID/GID 10001. Старый UI не умеет показывать property-группы. Восстановление backup теряет последующие изменения; не удаляйте volumes и не очищайте профиль.

Следующий раздел Phase 2 оставлен для обновления с более ранних версий: его требование пересобирать browser не относится к этому Phase 3 исправлению.

## Как работает browser collector

Основная кнопка — **«Поиск через браузер»**, источник CianBrowserSource. App обращается к внутреннему API browser service; Chromium не устанавливается в основной контейнер. Отдельный volume browser_profile (при проекте xata: xata_browser_profile) хранит профиль Chromium, cookies и сессию. Только app пишет SQLite через прежний save_items. ID ЦИАН объединяет CSV/browser/online; first_seen и старые объявления сохраняются, пустые поля не стирают заполненные. Источник показывает последнее обновление записи.

Обычный headed Chromium работает на Xvfb. Stealth, подмена fingerprint/UA, CAPTCHA-solving, мобильные API, извлечение токенов и reverse engineering не используются. Сбор читает отображаемые карточки через DOM и не открывает страницы объявлений. Получаются ID, URL, заголовок, цена, площадь, этаж, адрес, ЖК, метро, время и текст карточки/описание, если отображены и распознаны. Даты first_seen/last_seen выставляет сервер при сохранении. Нераспознанные необязательные поля остаются пустыми; исходный текст сохраняется.

Одна страница, максимум 100 карточек, без пагинации, прокрутки и повторных запросов к сайту. Скрытые CSS-элементы не читаются. Фильтры передаются в обычный URL поиска, цена дополнительно проверяется локально. Вторичку, комнаты, пешую доступность и актуальность проверяйте в оригинале.

При CAPTCHA, logout или дополнительном подтверждении вся текущая партия не сохраняется. Статус: **«Требуется ручное подтверждение в браузере»** / «Требуется вход». Старые объявления, CSV и XLSX доступны. Расписание приостанавливается до ручного действия. Откройте временный интерфейс, подтвердите лично, выключите интерфейс и повторите поиск кнопкой. Если защита остаётся — остановитесь и используйте CSV.

Статус сессии — последняя проверка DOM, а не гарантия бессрочной авторизации. После рестарта browser сообщает, что сессия ещё не проверена; профиль сохранён, следующий поиск проверит фактическую страницу. Видимые UserAvatar/ProfileMenu и кнопки входа — эвристики, требующие проверки на текущем ЦИАН.

CianOnlineSource и /api/collect оставлены для диагностики; UI и расписание используют browser. Общие ошибки: app/source_types.py, общий upsert: save_items в app/main.py.

## Первый вход: временный noVNC

Не создавайте для noVNC Proxy Host в NPM, DNS или проброс маршрутизатора. Основной compose вообще не публикует порты browser. Временный override публикует **только 172.31.1.1:6080**, без 0.0.0.0/IPv6. Raw VNC 5900 слушает только localhost контейнера, CDP не публикуется. API 8010 доступен в сети compose с Bearer-токеном.

1. В каталоге проекта с существующим .env соберите образы и создайте отдельный VNC-пароль:

~~~sh
docker compose -p xata build app browser
docker compose -p xata run --rm --no-deps --entrypoint python browser -m collector.vnc_password
~~~

Ввод интерактивный, пароль ровно 8 печатных ASCII-символов из-за ограничения стандартного VNC. Это **отдельный пароль noVNC, не пароль ЦИАН**. Он хранится в volume профиля с правами 0600, не в Git/.env. Не используйте APP_PASSWORD.

2. Включите временный интерфейс:

~~~sh
docker compose -p xata -f docker-compose.yml -f docker-compose.browser-login.yml config --quiet
docker compose -p xata -f docker-compose.yml -f docker-compose.browser-login.yml up -d --no-deps browser
~~~

В этом режиме сбор запрещён, чтобы не прерывать ручной вход.

3. На доверенном компьютере создайте SSH-туннель, заменив user@OMV:

~~~sh
ssh -N -L 127.0.0.1:16080:172.31.1.1:6080 user@OMV
~~~

Откройте http://127.0.0.1:16080/vnc.html и подключитесь к localhost:16080 с VNC-паролем. Прямой HTTP/noVNC в недоверенной сети не используйте: стандартный VNC не обеспечивает сильную защиту транспорта. IP-привязка не заменяет firewall: существующие правила OMV/Docker/маршрутизатора должны исключать интернет-доступ. NPM менять не требуется.

4. В адресной строке Chromium откройте https://www.cian.ru/ и лично войдите. Дополнительные подтверждения выполняйте вручную. Логин/пароль ЦИАН вводятся только на сайте; приложение не читает и не хранит их отдельно от обычного профиля. Профиль содержит чувствительную сессию — защищайте доступ и резервные копии.

5. Закройте noVNC и **выключите интерфейс**:

~~~sh
docker compose -p xata -f docker-compose.yml up -d --no-deps --force-recreate browser
docker compose -p xata ps
~~~

Профиль остаётся в том же volume, порт 6080 должен исчезнуть из ps. Закройте SSH-туннель. Не используйте override для обычного запуска.

6. В XATA нажмите «Поиск через браузер». Сверьте объявления с ЦИАН. После перезапуска browser повторите поиск и убедитесь, что сессия сохранилась, дублей нет и first_seen не изменился. При «Требуется вход» после успешного входа проверьте распознавание видимого меню профиля на текущем сайте.

Не запускайте второй Chromium с этим профилем. Browser использует файловую блокировку владельца профиля и asyncio.Lock поиска. App работает строго с одним Uvicorn worker. При OOM старые объявления остаются; проверьте docker stats и журналы.

## Расписание и search URL

После первого успешного ручного поиска добавьте в .env:

~~~dotenv
BROWSER_SCHEDULE_ENABLED=true
BROWSER_SEARCH_INTERVAL_SECONDS=1800
CIAN_SEARCH_URL=
~~~

Примените: docker compose -p xata up -d --no-deps app. Проверка выполняется раз в заданный период, без немедленного поиска при старте. Минимум — 1800 секунд; меньшее значение ограничивается 1800. Последний запуск хранится в SQLite, рестарт app не сбрасывает интервал. При занятом Chromium/app запуск пропускается, очередь не накапливается.

Ручной и плановый browser-поиск всегда используют один набор серверных критериев; старые filters из runs и клиентские budget/metro больше не используются. CIAN_SEARCH_URL может содержать обычный HTTPS URL поиска/сохранённого поиска ЦИАН. Пустое значение строит URL с defaults max_price=14_500_000 / metro_minutes=20. Из заданного безопасного CIAN_SEARCH_URL берутся maxprice и foot_min для локального price post-filter, записи run и информационного блока. Отсутствующие/невалидные/неоднозначные параметры используют defaults. Клиент /api/browser/collect отправляет только пустой запрос; произвольные фильтры отклоняются. Для изменения реального поиска владелец меняет только CIAN_SEARCH_URL в прежнем .env и пересоздаёт app; URL не публикуется через API/UI. Не помещайте пароль или секретную ссылку доступа в URL. Другие домены, HTTP и userinfo запрещены; главная навигация за пределы HTTPS cian.ru блокируется. Ресурсы страницы загружаются штатно.

По умолчанию расписание выключено до первого входа, интервал — 30 минут. Ручные запуски ограничены минутой. После CAPTCHA/login расписание не подтверждает вход автоматически; выполните ручное подтверждение и успешный поиск.

BROWSER_API_TOKEN — необязательный отдельный секрет API, минимум 16 символов; пустое значение использует APP_PASSWORD. Это не данные ЦИАН. Не публикуйте вывод docker compose config без --quiet: он содержит секреты.

## Импорт cian_favorites_*.csv

Нажмите **«Импортировать CSV»**, выберите локальный файл, проверьте количество найденных строк, уникальных объявлений, новых записей, обновлений и повторов. До нажатия **«Подтвердить импорт»** таблица объявлений не меняется. Показываются первые пять записей. Предпросмотр хранится до 30 минут; отмена удаляет его. Повторное подтверждение одного предпросмотра не выполняет импорт ещё раз. Если после предпросмотра другой импорт/онлайн-сбор изменил БД, итоговые числа новых/обновлённых записей могут отличаться — они пересчитываются при сохранении.

Ваш формат поддерживается непосредственно:

```csv
url;title;price;area;card_text
```

- `url` — обязательная ссылка на продажу квартиры Циан `/sale/flat/ID/`. Исходная ссылка сохраняется, включая параметры. Для сопоставления извлекается ID из пути: `www`, другой поддомен, HTTP/HTTPS и параметры не создают дубль.
- `title` — может быть пустым. При новом объявлении используется «Квартира»; при обновлении сохраняется прежний непустой заголовок.
- `price` — например `11 950 000 ₽`; `area` — `34,70 м²`. Пустые значения разрешены, некорректные непустые числа отклоняются с номером строки.
- `card_text` — исходный текст карточки сохраняется целиком, включая переносы строк. CSV-поля с переносами, кавычками или разделителем должны быть корректно заключены в двойные кавычки по правилам CSV.

Из `card_text` по распространённым шаблонам извлекаются этаж (`4/9 этаж`, `4 этаж из 9`), адрес с указанием Москвы, ЖК, станция после `м.`/`метро`, время в пути. **Распознавание приблизительное:** нераспознанные поля остаются пустыми или сохраняют прежнее значение. Минуты пешком записываются только при явном указании пешего маршрута около упоминания метро. `7 мин. транспортом` не превращается в пешую доступность; время без способа перемещения не считается пешим. Если есть маркер «Описание:», сохраняется текст после него; иначе описанием служит исходная карточка. Описание и исходный текст остаются в БД/диагностическом XLSX для внутреннего анализа, но больше не отображаются в интерфейсе.

Также распознаются отдельные столбцы `Адрес`, `ЖК`, `Этаж`, `Метро`, `Время до метро`, `Описание` и их английские аналоги. Непустые отдельные столбцы имеют приоритет над извлечёнными из текста. Кодировки: UTF-8 с BOM/без, UTF-16 с BOM, Windows-1251 (в этой кодировке используйте `руб.` и `м2`). Разделители: `;`, `,`, табуляция. Максимум: 5 МБ, 10 000 строк данных, 10 000 символов в одном распознаваемом поле.

Импорт работает полностью локально: не обращается к `cian.ru` и не зависит от CAPTCHA. Фильтры онлайн-поиска не отбрасывают строки CSV. Ошибка структуры или неверная ссылка останавливает весь предпросмотр, частичный импорт не выполняется. Повторы внутри файла объединяются; последние непустые значения имеют приоритет. При обновлении пустые поля не стирают старые. Старые объявления не удаляются автоматически.

Таблица содержит характеристики, ипотечный платёж и две независимые оценки. XLSX дополнительно содержит источник, даты последнего обновления/импорта, обе оценки с авторами/UTC-временем, комментарий риелтора и точный ипотечный платёж. Формульные префиксы экранируются и для новых текстовых полей. Источник означает источник **последнего обновления записи**: `ЦИАН CSV`, `ЦИАН browser` или `ЦИАН online`, а не полную историю происхождения каждого поля. Дата первого обнаружения сохраняется; дата последнего импорта меняется только при CSV-импорте, дата последнего обновления — при любом обновлении. Даты хранятся в UTC, браузер показывает их в своей временной зоне.

Модули: `CianOnlineSource` в `app/source.py`, `CianCsvSource` в `app/csv_source.py`, общие состояния источника в `app/source_types.py`. Все источники передают нормализованные словари в общий `save_items`; добавление нового источника не требует менять общий upsert для этих же полей.

## Безопасное обновление существующего OMV — Phase 2

Команды выполняет владелец, не Codex. Не меняйте NPM, neofart.ru, другие проекты, порт 3010, xata_xata_data или xata_browser_profile.

1. В прежнем каталоге проекта проверьте git status, git branch --show-current, docker compose ls. Сохраните git rev-parse HEAD для отката. Используйте проект **xata** и прежний .env. Убедитесь, что нет активного сбора и временный noVNC выключен. Проверьте существующие volumes:

~~~sh
docker inspect "$(docker compose -p xata ps -q app)" --format '{{range .Mounts}}{{println .Name .Destination}}{{end}}'
docker inspect "$(docker compose -p xata ps -q browser)" --format '{{range .Mounts}}{{println .Name .Destination}}{{end}}'
~~~

Для /data и /profile должны быть xata_xata_data и xata_browser_profile. Не создавайте новый проект/пустые volumes.

2. **До git pull и обновления** сделайте согласованную SQLite-копию и защищённую копию .env:

~~~sh
umask 077
mkdir -p backups
xata_stamp="$(date -u +%Y%m%dT%H%M%SZ)"
git rev-parse HEAD > "backups/xata-before-phase2-$xata_stamp.sha"
cp .env "backups/xata-before-phase2-$xata_stamp.env"
chmod 600 "backups/xata-before-phase2-$xata_stamp.env"
docker compose -p xata stop app
docker compose -p xata cp app:/data/xata.sqlite3 "backups/xata-before-phase2-$xata_stamp.sqlite3"
chmod 600 "backups/xata-before-phase2-$xata_stamp.sqlite3"
docker compose -p xata start app
~~~

Если копирование не удалось — запустите прежний app и устраните проблему; к обновлению не переходите. Проверьте размер SQLite и скопируйте backup вне сервера безопасным способом. БД содержит хеши/сессии, .env — секреты. Не публикуйте их. Никогда не выполняйте down -v, volume prune или очистку профиля.

3. Получите изменения и проверьте обе конфигурации без вывода секретов:

~~~sh
git switch xata/initial-app
git pull --ff-only origin xata/initial-app
docker compose -p xata config --quiet
docker compose -p xata -f docker-compose.yml -f docker-compose.browser-login.yml config --quiet
docker compose -p xata build app browser
~~~

В Phase 2 нужны оба образа: app содержит миграции/UI, browser — исправленный parser metro_time. Dockerfile.browser и security/runtime не меняются. Не используйте login override для обычного запуска.

4. Обновите только эти два сервиса с прежними volumes:

~~~sh
docker compose -p xata stop app
docker compose -p xata up -d --no-deps browser
docker compose -p xata up -d --no-deps app
docker compose -p xata ps
curl --fail http://172.31.1.1:3010/healthz
~~~

В браузере сохраняется прежний профиль, повторный вход в ЦИАН обычно не нужен. При миграции большой БД первый старт может занять больше времени. Проверьте health обоих сервисов и журналы app на ошибку миграции; не публикуйте .env/профиль.

5. Откройте https://xata.neofart.ru обычным обновлением страницы (без очистки кэша). Проверьте прежний вход, сохранность количества объявлений/ID/first_seen и оценок. Поставьте «Понравилось», проверьте фильтры и ↑/↓/default сортировку. Проверьте ипотеку (12 млн → примерно 96 600 ₽/мес.), read-only 14,5 млн/20 мин и last_success. Создайте риелтора с ролью «Риелтор»: он меняет только свою оценку/комментарий; семья читает их и меняет общий статус, администратор — оба. Проверьте права в отдельных окнах/сессиях.

6. Под администратором выполните browser smoke на реальном ЦИАН и убедитесь, что профиль авторизован; проверьте метро (никаких «сегодня/вчера»), CSV preview/confirm и XLSX. Повторное обновление объявления сохраняет обе оценки, комментарий и first_seen, а изменение цены пересчитывает ипотеку. Расписание сохраняет прежний cadence, но использует текущие server criteria вместо старых client filters.

7. Для отката сохраните копию уже обновлённой БД, затем остановите только app, переключитесь на записанный прежний SHA и пересоберите app/browser. Старый UI не понимает liked/realtor: для полного отката используйте согласованную pre-Phase2 SQLite-копию при остановленном app. Восстановление теряет изменения после backup; заранее сохраните их копию. Прежний код и .env должны соответствовать этой копии. При восстановлении оставляйте файл в прежнем /data и владельца UID/GID 10001. Не удаляйте volume, не трогайте профиль Chromium и не останавливайте весь Docker/OMV. Если не уверены в восстановлении — оставьте app остановленным и разберите ошибку миграции, не запускайте новый пустой проект.


Основной контейнер остаётся UID/GID 10001, без Chromium, 384 МБ/1 CPU, 172.31.1.1:3010 -> 8000. Browser: UID/GID 10001, 1 ГБ, <=1 CPU, shm 256 МБ, pids 256, restart unless-stopped, read-only root и tmpfs. Образ браузера существенно больше основного; предусмотрите несколько ГБ диска. Профиль со временем растёт.

Browser использует обычные параметры Playwright, включая стандартное отключение внутреннего Chromium sandbox; контейнер ограничен non-root, cap_drop ALL и no-new-privileges. Не подключайте host network, Docker socket, каталоги OMV или посторонние секреты. Это ограничение изоляции учитывайте при ручном просмотре; главная навигация разрешена только на ЦИАН.

## Просмотры и сравнение квартир

«Дата просмотра» показывает ближайшую назначенную встречу либо последний состоявшийся просмотр; заголовок сортирует именно эту дату. Семья и администратор записывают один общий результат, отдельные заметки до/после поездки и необязательные причины отказа. «Ближайшие просмотры» включает просроченные и ещё не отменённые встречи по отказам. Можно сравнить 2–4 квартиры из основного списка без изменения оценок.

[Поведение, миграция и команды безопасного обновления OMV](docs/XATA_VIEWINGS.md). Для этой доработки относительно версии 255f8dec пересобирается только **app**; collector и browser не менялись.

## Заглавное фото объявления

Первая колонка «Фото» показывает одну локальную миниатюру с увеличением по клику; рекламный текст автора скрыт, но сохранён в БД. Источник — первое видимое изображение карточки в обычном browser DOM. Файлы находятся в существующем /data/images/listings, без галереи и без дополнительного перехода в объявление. Старые записи работают с placeholder и заполняются при следующем обычном обновлении. Ошибка фото не отменяет импорт.

[Схема, ограничения, тесты и безопасное обновление OMV](docs/XATA_COVER_PHOTOS.md). Для этого обновления пересоберите **app и browser**; compose, порт 3010 и оба persistent volume остаются прежними.

## Эксплуатация

- /healthz app проверяет SQLite; /healthz browser — живой Chromium, а не доступность/авторизацию ЦИАН.
- docker compose -p xata logs --tail=100 app browser — диагностика. Не публикуйте cookies, профиль, screenshots входа или .env.
- Недоступен browser: проверьте health, одинаковый BROWSER_API_TOKEN и доступность browser:8010 внутри compose. API на хост публиковать не нужно.
- CAPTCHA/login: включите noVNC, подтвердите лично, отключите noVNC, запустите вручную. Автоматического обхода нет.
- «Требуется вход» при авторизованной странице / «Не распознана обычная выдача»: проверьте DOM-селекторы collector/page.py на OMV, не заменяйте закрытым API.
- Последний успешный поиск и число новых остаются при ошибке/рестарте. Последняя ошибка очищается успешным поиском. Старые объявления не удаляются.
- HTTP 403 на изменение: проверьте PUBLIC_URL и актуальность CSRF/сессии, обновите страницу входа. HTTP 503 при первом входе: для bootstrap нужны APP_USER и APP_PASSWORD от 16 символов. После создания users значения .env пароль XATA не меняют.
- CSV, /api/state и XLSX не зависят от browser/ЦИАН.
- Резервируйте профиль при остановленном browser. Не используйте одну копию в двух Chromium одновременно.
