# Хата — личный поиск квартир

Лёгкое приложение для Debian 13 / OMV: FastAPI, статический интерфейс и SQLite в одном контейнере. Отдельные Node.js, Redis, PostgreSQL не нужны. Домен: `https://xata.neofart.ru`, задаётся через `PUBLIC_URL`.

## Что реализовано и что ещё не подтверждено

Фильтры по умолчанию: Москва, покупка, вторичка, одна комната, до 14 млн ₽, до метро 20 минут пешком. Цена и минуты редактируются. Интерфейс показывает историю объявлений, статус последнего онлайн-запуска и экспортирует XLSX. Есть независимый импорт CSV через браузер. Онлайн-сбор — ручной запрос одной страницы, без расписания и обхода защиты.

**Реальный сбор не подтверждён:** при проверке из среды разработки Циан ответил перенаправлением на `/tmgrdfrend/showcaptcha`. Онлайн-запуск получает штатный статус `blocked`, приложение и CSV-импорт продолжают работать. CAPTCHA не записывается как авария с traceback. Источник `app/source.py` поддерживает публичные JSON-LD `Apartment`/`Product`/`RealEstateListing` с ценой и ссылкой объявления. Совместимость этого формата с текущей выдачей Циан не подтверждена. Если сайт не отдаёт такой формат, сбор завершится явной ошибкой; потребуется адаптировать модуль к разрешённому источнику данных. Наличие рабочего интерфейса не означает, что сбор уже работает.

Параметры вторички, комнаты и метро передаются в URL поиска; их применение сайтом не подтверждено и не проверяется независимо парсером. Цена дополнительно проверяется локально. Онлайн-парсер пока не извлекает площадь, этаж, метро и описание. Эти поля можно получить из CSV; разбор свободного текста приблизительный. Проверяйте характеристики в оригинале. Сохранённые строки — история, а не гарантированно актуальные предложения; старые объявления не удаляются. XLSX включает всю историю.

## Импорт cian_favorites_*.csv

Нажмите **«Импортировать CSV»**, выберите локальный файл, проверьте количество найденных строк, уникальных объявлений, новых записей, обновлений и повторов. До нажатия **«Подтвердить импорт»** таблица объявлений не меняется. Показываются первые пять записей. Предпросмотр хранится до 30 минут; отмена удаляет его. Повторное подтверждение одного предпросмотра не выполняет импорт ещё раз. Если после предпросмотра другой импорт/онлайн-сбор изменил БД, итоговые числа новых/обновлённых записей могут отличаться — они пересчитываются при сохранении.

Ваш формат поддерживается непосредственно:

```csv
url;title;price;area;card_text
```

- `url` — обязательная ссылка на продажу квартиры Циан `/sale/flat/ID/`. Исходная ссылка сохраняется, включая параметры. Для сопоставления извлекается ID из пути: `www`, другой поддомен, HTTP/HTTPS и параметры не создают дубль.
- `title` — может быть пустым. При новом объявлении используется «Квартира»; при обновлении сохраняется прежний непустой заголовок.
- `price` — например `11 950 000 ₽`; `area` — `34,70 м²`. Пустые значения разрешены, некорректные непустые числа отклоняются с номером строки.
- `card_text` — исходный текст карточки сохраняется целиком, включая переносы строк. CSV-поля с переносами, кавычками или разделителем должны быть корректно заключены в двойные кавычки по правилам CSV.

Из `card_text` по распространённым шаблонам извлекаются этаж (`4/9 этаж`, `4 этаж из 9`), адрес с указанием Москвы, ЖК, станция после `м.`/`метро`, время в пути. **Распознавание приблизительное:** нераспознанные поля остаются пустыми или сохраняют прежнее значение. Минуты пешком записываются только при явном указании пешего маршрута около упоминания метро. `7 мин. транспортом` не превращается в пешую доступность; время без способа перемещения не считается пешим. Если есть маркер «Описание:», сохраняется текст после него; иначе описанием служит исходная карточка. Проверьте извлечённые значения по исходному тексту, доступному в раскрываемом блоке таблицы.

Также распознаются отдельные столбцы `Адрес`, `ЖК`, `Этаж`, `Метро`, `Время до метро`, `Описание` и их английские аналоги. Непустые отдельные столбцы имеют приоритет над извлечёнными из текста. Кодировки: UTF-8 с BOM/без, UTF-16 с BOM, Windows-1251 (в этой кодировке используйте `руб.` и `м2`). Разделители: `;`, `,`, табуляция. Максимум: 5 МБ, 10 000 строк данных, 10 000 символов в одном распознаваемом поле.

Импорт работает полностью локально: не обращается к `cian.ru` и не зависит от CAPTCHA. Фильтры онлайн-поиска не отбрасывают строки CSV. Ошибка структуры или неверная ссылка останавливает весь предпросмотр, частичный импорт не выполняется. Повторы внутри файла объединяются; последние непустые значения имеют приоритет. При обновлении пустые поля не стирают старые. Старые объявления не удаляются автоматически.

Таблица и XLSX содержат ЖК/адрес, цену, площадь, этаж, метро, время до метро, исходную ссылку, дату первого обнаружения, дату последнего обновления, последнего импорта и источник. Источник означает источник **последнего обновления записи**: `ЦИАН CSV` или `ЦИАН online`, а не полную историю происхождения каждого поля. Дата первого обнаружения сохраняется; дата последнего импорта меняется только при CSV-импорте, дата последнего обновления — при любом обновлении. Даты хранятся в UTC, браузер показывает их в своей временной зоне.

Модули: `CianOnlineSource` в `app/source.py`, `CianCsvSource` в `app/csv_source.py`, общие состояния источника в `app/source_types.py`. Оба источника передают нормализованные словари в общий `save_items`; добавление нового источника не требует менять существующую схему таблицы или интерфейс для этих же полей.

## Запуск на OMV

Используйте отдельную директорию, например `/opt/xata`. Не меняйте существующие compose-проекты и NPM. Команды ниже выполняются из директории этого проекта.

1. Скопируйте `.env.example` в `.env`, задайте свой `APP_USER` и уникальный `APP_PASSWORD` длиной от 16 символов. Не публикуйте `.env`. Для генерации пароля можно использовать `openssl rand -hex 24` локально на сервере.
2. Проверьте адрес: `ip -brief address`. IP `172.31.1.1` должен принадлежать хосту OMV и быть доступен из контейнера NPM. Проверьте, что порт не занят: `ss -ltn '( sport = :3010 )'`. При необходимости измените `BIND_IP` в `.env` на внутренний адрес сервера. Не используйте `0.0.0.0` и не создавайте проброс порта 3010 на маршрутизаторе. IP-привязка не заменяет firewall: проверьте правила OMV, Docker и маршрутизатора.
3. Запустите:

   ```sh
   docker compose -p xata config --quiet
   docker compose -p xata up -d --build
   docker compose -p xata ps
   curl --fail http://172.31.1.1:3010/healthz
   ```

4. В **Nginx Proxy Manager** создайте отдельный Proxy Host: домен `xata.neofart.ru`, Scheme `http`, Forward Hostname/IP `172.31.1.1`, Forward Port `3010`. Включите сертификат Let's Encrypt и Force SSL. Basic Auth приложения передаётся обычным заголовком Authorization; не настраивайте второй Basic Auth NPM поверх него. Само приложение слушает `0.0.0.0:8000` **в контейнере**, на хосте порт публикуется только на `BIND_IP:APP_PORT`.
5. DNS A должен указывать на внешний адрес вашего сервера; AAAA добавляйте только при рабочем IPv6. Доступ из интернета идёт через существующие порты NPM 80/443. При CGNAT одного DNS недостаточно.
6. Откройте домен, войдите с данными из `.env`, импортируйте CSV или запустите онлайн-сбор. При CAPTCHA/HTTP-ошибке прочтите статус и `docker compose -p xata logs --tail=100 app`. Не обходите ограничения Циан.

Контейнер работает от UID/GID 10001, с read-only корневой системой, временным `/tmp`, лимитами 384 МБ и одного CPU. SQLite хранится в named volume `xata_xata_data` при использовании `-p xata`. `docker compose down` сохраняет данные; **`down -v` удаляет базу**. Не подменяйте named volume каталогом OMV без подготовки прав UID/GID 10001.

### Резервная копия и обновление

Для согласованной копии остановите только этот сервис:

```sh
mkdir -p backups
docker compose -p xata stop app
docker compose -p xata cp app:/data/xata.sqlite3 ./backups/xata.sqlite3
docker compose -p xata start app
```

Сохраните резервную копию вне сервера. Если установлен проект из ветки `xata/initial-app`, после резервного копирования выполните:

```sh
git pull --ff-only origin xata/initial-app
docker compose -p xata up -d --build app
docker compose -p xata ps
```

Используйте **то же имя compose-проекта и тот же volume, что при первом запуске**. Если изначально запускали без `-p xata`, не добавляйте его вслепую: сначала проверьте `docker compose ls` и используйте существующий проект. Новые столбцы добавляются при запуске автоматически; старая БД и `first_seen` сохраняются, миграция повторяема. `.env`, ports, volumes и конфигурация NPM этим обновлением не меняются. Не выполняйте `down -v`. После обновления при необходимости обновите страницу с очисткой кэша (Ctrl+F5). Существующие сервисы эти команды не затрагивают.

### Диагностика

- Unhealthy: проверьте журналы и доступ на запись к `/data`.
- HTTP 503: задайте имя и пароль от 16 символов в `.env`, пересоздайте контейнер через `up -d`.
- HTTP 403 при нажатии сбора: `PUBLIC_URL` должен точно совпадать с HTTPS-адресом в браузере, без пути.
- HTTP 429 онлайн-сбора: минимальный интервал между запусками 60 секунд. Для CSV он не применяется. До 10 активных предпросмотров одновременно; отменяйте ненужные или дождитесь их истечения.
- CSV: ошибка структуры показывает причину и строку; неизвестные столбцы игнорируются, столбец URL обязателен. При ошибке HTTP 413 на NPM проверьте лимит `client_max_body_size` этого Proxy Host: для файлов до 5 МБ он должен быть не меньше 5 МБ.
- HTTP 302/CAPTCHA/нет поддерживаемых данных: сбор остановлен; прежние данные остаются. Нужна проверка разрешённого источника, а не обход защиты.

`/healthz` проверяет приложение и доступ к SQLite, а не доступность Циан. Журналы Docker ограничены 3 файлами по 5 МБ. История SQLite пока не очищается автоматически. Один Uvicorn worker обязателен для блокировки одновременного сбора.

## Локальная разработка

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/pip install pytest==8.3.5
.venv/bin/python -m pytest -q
```

Для запуска задайте `APP_USER`, `APP_PASSWORD`, необязательно `DATA_DIR` и `PUBLIC_URL`, затем `.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000`. Секреты задавайте локально, не сохраняйте в Git. `PUBLIC_URL` для локального HTTP можно не задавать. Тесты используют временную БД и искусственный JSON-LD, не являются проверкой реальной выдачи Циан.
