# ХАТА — совместный выбор квартиры

FastAPI + SQLite + статический интерфейс; отдельный browser service с обычным Playwright/Chromium. Домен: https://xata.neofart.ru. CSV остаётся независимым резервным импортом.

По сообщению владельца, browser collector и сохранённая сессия ЦИАН уже работают на OMV. В этой доработке collector, его snapshot/CAPTCHA/login, профиль, noVNC, расписание, search URL, Docker Compose и browser image не изменяются. CI использует искусственные страницы; реальный ЦИАН в этой среде не проверяется.

## Пользователи и просмотр объявлений

XATA использует обычную страницу /login, SQLite users и серверные сессии вместо HTTP Basic. При первом запуске с пустой users создаётся администратор из существующих APP_USER / APP_PASSWORD (пароль от 16 символов). Миграция повторяема, уже созданный пользователь не перезаписывается значениями .env. Логин регистронезависимый, крайние пробелы игнорируются.

Откройте «Пользователи» под таблицей: создайте отдельные аккаунты для семьи и риелтора. Роль **«Просмотр»** может читать объявления и менять статусы. Только **администратор** запускает сбор, видит состояние browser collector, импортирует CSV, экспортирует XLSX и управляет пользователями. Ограничения проверяются сервером, включая прямые API-запросы. Аккаунты отключаются вместо удаления; последнего активного администратора нельзя отключить или перевести в роль просмотра.

Пароли хешируются Argon2id (19 МиБ, 2 прохода, parallelism 1). Сессионная cookie __Host-xata_session — Secure, HttpOnly, SameSite=Lax, Path=/, срок 7 дней; в БД хранится только SHA-256 случайного идентификатора сессии. Выход отзывает текущую сессию. Отключение пользователя или смена его пароля отзывает все его сессии. Роли и enabled читаются из БД при каждом запросе. Ограничение неудачных входов — 20 за 15 минут на адрес приложения; за NPM этот адрес может быть общим для посетителей. Пароли, хеши, session/CSRF/cookies не логируются и не возвращаются в API.

Вход и все изменения защищены CSRF-токенами; проверки Origin / Sec-Fetch-Site и CSP сохранены. JavaScript получает CSRF через /api/auth/csrf перед входом и /api/auth/me после входа. Секреты не сохраняются в localStorage/sessionStorage. Для входа требуется **HTTPS**: за существующим NPM Secure-cookie работает штатно, порт и настройки proxy не меняются. В локальных API-тестах используется HTTPS TestClient; для ручной локальной разработки настройте локальный HTTPS, не отключайте Secure.

Таблица использует ширину рабочего стола, ID ЦИАН — ссылка в первом столбце. Статусы **НОВОЕ / Просмотрено / Не подходит** общие для всех пользователей. Рядом видны последний автор и время; даты в БД — UTC, в интерфейсе — часовой пояс браузера. Сначала новые, затем просмотренные и неподходящие, внутри группы новые first_seen выше. Фильтры работают по уже загруженным данным. Статусы не стираются сборщиком/CSV. Версия review_version защищает UI от устаревшего ответа автообновления. Источник, last_seen и last_imported остаются в SQLite/API/XLSX, но не занимают столбцы экранной таблицы.

Новые столбцы listings: review_status (default new), review_updated_at, review_updated_by (стабильный users.id), review_version. Новые таблицы: users, sessions, login_challenges, login_attempts; новые индексы для сессий и сортировки просмотра. Таблицы не пересоздаются, ID, first_seen, история runs/browser_state/import_previews сохраняются. Переименование пользователя не меняет ID автора; отображается его текущее имя.

APP_USER/APP_PASSWORD остаются в вашем .env для безопасного bootstrap и существующего fallback внутреннего browser API. После bootstrap они **не являются паролем входа XATA**: меняйте пароли через панель пользователей. Смена пароля XATA не меняет пароль ЦИАН и BROWSER_API_TOKEN. Не меняйте существующие значения .env вслепую: при пустом BROWSER_API_TOKEN APP_PASSWORD по-прежнему нужен обоим сервисам для внутренней связи.


## Как работает browser collector

Основная кнопка — **«Поиск через браузер»**, источник CianBrowserSource. App обращается к внутреннему API browser service; Chromium не устанавливается в основной контейнер. Отдельный volume browser_profile (при проекте xata: xata_browser_profile) хранит профиль Chromium, cookies и сессию. Только app пишет SQLite через прежний save_items. ID ЦИАН объединяет CSV/browser/online; first_seen и старые объявления сохраняются, пустые поля не стирают заполненные. Источник показывает последнее обновление записи.

Обычный headed Chromium работает на Xvfb. Stealth, подмена fingerprint/UA, CAPTCHA-solving, мобильные API, извлечение токенов и reverse engineering не используются. Сбор читает отображаемые карточки через DOM и не открывает страницы объявлений. Получаются ID, URL, заголовок, цена, площадь, этаж, адрес, ЖК, метро, время и текст карточки/описание, если отображены и распознаны. Даты first_seen/last_seen выставляет сервер при сохранении. Нераспознанные необязательные поля остаются пустыми; исходный текст сохраняется.

Одна страница, максимум 100 карточек, без пагинации, прокрутки и повторных запросов к сайту. Скрытые CSS-элементы не читаются. Фильтры передаются в обычный URL поиска, цена дополнительно проверяется локально. Вторичку, комнаты, пешую доступность и актуальность проверяйте в оригинале.

При CAPTCHA, logout или дополнительном подтверждении вся текущая партия не сохраняется. Статус: **«Требуется ручное подтверждение в браузере»** / «Требуется вход». Старые объявления, CSV и XLSX доступны. Расписание приостанавливается до ручного действия. Откройте временный интерфейс, подтвердите лично, выключите интерфейс и повторите поиск кнопкой. Если защита остаётся — остановитесь и используйте CSV.

Статус сессии — последняя проверка DOM, а не гарантия бессрочной авторизации. После рестарта browser сообщает, что сессия ещё не проверена; профиль сохранён, следующий поиск проверит фактическую страницу. Видимые UserAvatar/ProfileMenu и кнопки входа — эвристики, требующие проверки на текущем ЦИАН.

CianOnlineSource и /api/collect оставлены для диагностики; UI и расписание используют browser. Общие ошибки: app/source_types.py, общий upsert: save_items в app/main.py.

## Первый вход: временный noVNC

Не создавайте для noVNC Proxy Host в NPM, DNS или проброс маршрутизатора. Основной compose вообще не публикует порты browser. Временный override публикует **только 172.31.1.1:6080**, без 0.0.0.0/IPv6. Raw VNC 5900 слушает только localhost контейнера, CDP не публикуется. API 8010 доступен в сети compose с Bearer-токеном.

1. В каталоге проекта с существующим .env соберите образы и создайте отдельный VNC-пароль:

~~~sh
docker compose -p xata build app browser
docker compose -p xata run --rm --no-deps --entrypoint python browser -m collector.vnc_password
~~~

Ввод интерактивный, пароль ровно 8 печатных ASCII-символов из-за ограничения стандартного VNC. Это **отдельный пароль noVNC, не пароль ЦИАН**. Он хранится в volume профиля с правами 0600, не в Git/.env. Не используйте APP_PASSWORD.

2. Включите временный интерфейс:

~~~sh
docker compose -p xata -f docker-compose.yml -f docker-compose.browser-login.yml config --quiet
docker compose -p xata -f docker-compose.yml -f docker-compose.browser-login.yml up -d --no-deps browser
~~~

В этом режиме сбор запрещён, чтобы не прерывать ручной вход.

3. На доверенном компьютере создайте SSH-туннель, заменив user@OMV:

~~~sh
ssh -N -L 127.0.0.1:16080:172.31.1.1:6080 user@OMV
~~~

Откройте http://127.0.0.1:16080/vnc.html и подключитесь к localhost:16080 с VNC-паролем. Прямой HTTP/noVNC в недоверенной сети не используйте: стандартный VNC не обеспечивает сильную защиту транспорта. IP-привязка не заменяет firewall: существующие правила OMV/Docker/маршрутизатора должны исключать интернет-доступ. NPM менять не требуется.

4. В адресной строке Chromium откройте https://www.cian.ru/ и лично войдите. Дополнительные подтверждения выполняйте вручную. Логин/пароль ЦИАН вводятся только на сайте; приложение не читает и не хранит их отдельно от обычного профиля. Профиль содержит чувствительную сессию — защищайте доступ и резервные копии.

5. Закройте noVNC и **выключите интерфейс**:

~~~sh
docker compose -p xata -f docker-compose.yml up -d --no-deps --force-recreate browser
docker compose -p xata ps
~~~

Профиль остаётся в том же volume, порт 6080 должен исчезнуть из ps. Закройте SSH-туннель. Не используйте override для обычного запуска.

6. В XATA нажмите «Поиск через браузер». Сверьте объявления с ЦИАН. После перезапуска browser повторите поиск и убедитесь, что сессия сохранилась, дублей нет и first_seen не изменился. При «Требуется вход» после успешного входа проверьте распознавание видимого меню профиля на текущем сайте.

Не запускайте второй Chromium с этим профилем. Browser использует файловую блокировку владельца профиля и asyncio.Lock поиска. App работает строго с одним Uvicorn worker. При OOM старые объявления остаются; проверьте docker stats и журналы.

## Расписание и search URL

После первого успешного ручного поиска добавьте в .env:

~~~dotenv
BROWSER_SCHEDULE_ENABLED=true
BROWSER_SEARCH_INTERVAL_SECONDS=1800
CIAN_SEARCH_URL=
~~~

Примените: docker compose -p xata up -d --no-deps app. Проверка выполняется раз в заданный период, без немедленного поиска при старте. Минимум — 1800 секунд; меньшее значение ограничивается 1800. Последний запуск хранится в SQLite, рестарт app не сбрасывает интервал. При занятом Chromium/app запуск пропускается, очередь не накапливается.

Используются последние параметры browser-поиска. CIAN_SEARCH_URL может содержать обычный HTTPS URL поиска/сохранённого поиска ЦИАН. Пустое значение строит URL из фильтров интерфейса. Указанный URL имеет приоритет над параметрами URL, но бюджет интерфейса ограничивает сохраняемые результаты. Не помещайте пароль или секретную ссылку доступа в URL. Другие домены, HTTP и userinfo запрещены; главная навигация за пределы HTTPS cian.ru блокируется. Ресурсы страницы загружаются штатно.

По умолчанию расписание выключено до первого входа, интервал — 30 минут. Ручные запуски ограничены минутой. После CAPTCHA/login расписание не подтверждает вход автоматически; выполните ручное подтверждение и успешный поиск.

BROWSER_API_TOKEN — необязательный отдельный секрет API, минимум 16 символов; пустое значение использует APP_PASSWORD. Это не данные ЦИАН. Не публикуйте вывод docker compose config без --quiet: он содержит секреты.

## Импорт cian_favorites_*.csv

Нажмите **«Импортировать CSV»**, выберите локальный файл, проверьте количество найденных строк, уникальных объявлений, новых записей, обновлений и повторов. До нажатия **«Подтвердить импорт»** таблица объявлений не меняется. Показываются первые пять записей. Предпросмотр хранится до 30 минут; отмена удаляет его. Повторное подтверждение одного предпросмотра не выполняет импорт ещё раз. Если после предпросмотра другой импорт/онлайн-сбор изменил БД, итоговые числа новых/обновлённых записей могут отличаться — они пересчитываются при сохранении.

Ваш формат поддерживается непосредственно:

```csv
url;title;price;area;card_text
```

- `url` — обязательная ссылка на продажу квартиры Циан `/sale/flat/ID/`. Исходная ссылка сохраняется, включая параметры. Для сопоставления извлекается ID из пути: `www`, другой поддомен, HTTP/HTTPS и параметры не создают дубль.
- `title` — может быть пустым. При новом объявлении используется «Квартира»; при обновлении сохраняется прежний непустой заголовок.
- `price` — например `11 950 000 ₽`; `area` — `34,70 м²`. Пустые значения разрешены, некорректные непустые числа отклоняются с номером строки.
- `card_text` — исходный текст карточки сохраняется целиком, включая переносы строк. CSV-поля с переносами, кавычками или разделителем должны быть корректно заключены в двойные кавычки по правилам CSV.

Из `card_text` по распространённым шаблонам извлекаются этаж (`4/9 этаж`, `4 этаж из 9`), адрес с указанием Москвы, ЖК, станция после `м.`/`метро`, время в пути. **Распознавание приблизительное:** нераспознанные поля остаются пустыми или сохраняют прежнее значение. Минуты пешком записываются только при явном указании пешего маршрута около упоминания метро. `7 мин. транспортом` не превращается в пешую доступность; время без способа перемещения не считается пешим. Если есть маркер «Описание:», сохраняется текст после него; иначе описанием служит исходная карточка. Проверьте извлечённые значения по исходному тексту, доступному в раскрываемом блоке таблицы.

Также распознаются отдельные столбцы `Адрес`, `ЖК`, `Этаж`, `Метро`, `Время до метро`, `Описание` и их английские аналоги. Непустые отдельные столбцы имеют приоритет над извлечёнными из текста. Кодировки: UTF-8 с BOM/без, UTF-16 с BOM, Windows-1251 (в этой кодировке используйте `руб.` и `м2`). Разделители: `;`, `,`, табуляция. Максимум: 5 МБ, 10 000 строк данных, 10 000 символов в одном распознаваемом поле.

Импорт работает полностью локально: не обращается к `cian.ru` и не зависит от CAPTCHA. Фильтры онлайн-поиска не отбрасывают строки CSV. Ошибка структуры или неверная ссылка останавливает весь предпросмотр, частичный импорт не выполняется. Повторы внутри файла объединяются; последние непустые значения имеют приоритет. При обновлении пустые поля не стирают старые. Старые объявления не удаляются автоматически.

Таблица содержит характеристики и статус просмотра. XLSX дополнительно содержит источник, даты последнего обновления/импорта, статус, имя автора и UTC-время изменения статуса. Источник означает источник **последнего обновления записи**: `ЦИАН CSV`, `ЦИАН browser` или `ЦИАН online`, а не полную историю происхождения каждого поля. Дата первого обнаружения сохраняется; дата последнего импорта меняется только при CSV-импорте, дата последнего обновления — при любом обновлении. Даты хранятся в UTC, браузер показывает их в своей временной зоне.

Модули: `CianOnlineSource` в `app/source.py`, `CianCsvSource` в `app/csv_source.py`, общие состояния источника в `app/source_types.py`. Все источники передают нормализованные словари в общий `save_items`; добавление нового источника не требует менять существующую схему таблицы или интерфейс для этих же полей.

## Безопасное обновление существующего OMV

Команды ниже выполняет владелец. Deployment автоматически не выполняется. Не меняйте NPM, neofart.ru, другие проекты, порт 3010, xata_xata_data или xata_browser_profile.

1. В прежнем каталоге проекта проверьте git status, git branch --show-current, docker compose ls. Используйте проект **xata** и прежний .env. Запишите git rev-parse HEAD для отката. Проверьте, что app по-прежнему использует xata_xata_data:

~~~sh
docker inspect "$(docker compose -p xata ps -q app)" --format '{{range .Mounts}}{{println .Name .Destination}}{{end}}'
~~~

Для /data должен быть указан существующий xata_xata_data. Не запускайте новый проект с другим именем/пустым volume.

2. Сначала сделайте согласованную резервную копию SQLite. Остановите **только app**; browser и его профиль остаются в работе:

~~~sh
umask 077
mkdir -p backups
docker compose -p xata stop app
xata_backup="backups/xata-before-multiuser-$(date -u +%Y%m%dT%H%M%SZ).sqlite3"
docker compose -p xata cp app:/data/xata.sqlite3 "$xata_backup"
chmod 600 "$xata_backup"
docker compose -p xata start app
~~~

Если копирование не удалось — сначала запустите прежний app и устраните проблему; к обновлению не переходите. Проверьте размер копии, сохраните её вне сервера вместе с защищённой копией .env. Будущие SQLite-копии содержат пользователей, хеши и сессии — храните их как секрет. Не выполняйте down -v, volume prune и не очищайте профиль Chromium.

3. Получите изменения, проверьте конфигурацию и обновите **только основной app**:

~~~sh
git switch xata/initial-app
git pull --ff-only origin xata/initial-app
docker compose -p xata config --quiet
docker compose -p xata -f docker-compose.yml -f docker-compose.browser-login.yml config --quiet
docker compose -p xata build app
docker compose -p xata up -d --no-deps app
docker compose -p xata ps
curl --fail http://172.31.1.1:3010/healthz
~~~

Существующий browser не пересобирается и не пересоздаётся. Временный login override здесь только валидируется, интерфейс noVNC не включается. Compose, volumes, ограничения browser и .env этой доработкой не меняются. В основном Dockerfile добавлены зависимости Argon2id из requirements-app.txt; browser использует прежние requirements.

4. Откройте https://xata.neofart.ru с Ctrl+F5. Войдите в форму с прежними APP_USER/APP_PASSWORD. Проверьте сохранённые объявления/first_seen и новый статус НОВОЕ у прежних строк. В «Пользователи» создайте отдельные аккаунты супруги и риелтора с ролью «Просмотр». Проверьте в отдельном окне браузера: просмотрщик меняет статус, видит автора/время и не получает доступ к поиску, импорту, XLSX или пользователям.

5. Под администратором проверьте прежний browser-поиск и сохранённую сессию ЦИАН, CSV preview/confirm и XLSX. Статусы просмотра должны сохраняться при повторном обновлении объявления. Старое расписание и CIAN_SEARCH_URL продолжают действовать; повторно входить в ЦИАН или создавать новый профиль не нужно.

6. Если нужен откат, остановите только app. Перейдите на записанный прежний commit, пересоберите app и запустите с теми же проектом/volume:

~~~sh
docker compose -p xata stop app
git switch --detach PREVIOUS_SHA
docker compose -p xata build app
docker compose -p xata up -d --no-deps app
~~~

Замените PREVIOUS_SHA сохранённым commit. Старый код игнорирует добавленные поля/таблицы, но вернёт прежнюю модель Basic Auth. Users/review данные останутся в БД для повторного обновления. Резервную БД восстанавливайте только при необходимости и остановленном app: восстановление удалит изменения после даты копии. Сохраняйте владельца файла UID/GID 10001 и прежний volume. Не останавливайте весь Docker/OMV.


Основной контейнер остаётся UID/GID 10001, без Chromium, 384 МБ/1 CPU, 172.31.1.1:3010 -> 8000. Browser: UID/GID 10001, 1 ГБ, <=1 CPU, shm 256 МБ, pids 256, restart unless-stopped, read-only root и tmpfs. Образ браузера существенно больше основного; предусмотрите несколько ГБ диска. Профиль со временем растёт.

Browser использует обычные параметры Playwright, включая стандартное отключение внутреннего Chromium sandbox; контейнер ограничен non-root, cap_drop ALL и no-new-privileges. Не подключайте host network, Docker socket, каталоги OMV или посторонние секреты. Это ограничение изоляции учитывайте при ручном просмотре; главная навигация разрешена только на ЦИАН.

## Эксплуатация

- /healthz app проверяет SQLite; /healthz browser — живой Chromium, а не доступность/авторизацию ЦИАН.
- docker compose -p xata logs --tail=100 app browser — диагностика. Не публикуйте cookies, профиль, screenshots входа или .env.
- Недоступен browser: проверьте health, одинаковый BROWSER_API_TOKEN и доступность browser:8010 внутри compose. API на хост публиковать не нужно.
- CAPTCHA/login: включите noVNC, подтвердите лично, отключите noVNC, запустите вручную. Автоматического обхода нет.
- «Требуется вход» при авторизованной странице / «Не распознана обычная выдача»: проверьте DOM-селекторы collector/page.py на OMV, не заменяйте закрытым API.
- Последний успешный поиск и число новых остаются при ошибке/рестарте. Последняя ошибка очищается успешным поиском. Старые объявления не удаляются.
- HTTP 403 на изменение: проверьте PUBLIC_URL и актуальность CSRF/сессии, обновите страницу входа. HTTP 503 при первом входе: для bootstrap нужны APP_USER и APP_PASSWORD от 16 символов. После создания users значения .env пароль XATA не меняют.
- CSV, /api/state и XLSX не зависят от browser/ЦИАН.
- Резервируйте профиль при остановленном browser. Не используйте одну копию в двух Chromium одновременно.

Для тестов искусственной DOM и persistent profile:

~~~sh
.venv/bin/python -m playwright install --with-deps chromium
RUN_BROWSER_TESTS=1 .venv/bin/python -m pytest -q tests/test_browser_dom.py tests/test_ui.py
~~~

.github/workflows/xata-checks.yml выполняет старые и новые API-тесты (миграция, сессии, роли, CSRF, сохранение review), Node-проверку устаревших ответов, browser UI на искусственных страницах и тесты, обе проверки compose, JS, сборку Dockerfile и локальный smoke healthcheck browser без ЦИАН. Тестовые страницы перехватываются Playwright; настоящие учётные данные не нужны. Эти проверки не подтверждают реальный сбор, авторизацию или ресурсы OMV.
